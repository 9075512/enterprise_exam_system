# 企业内部在线考试系统使用说明与部署教程

本文面向系统管理员、出题人、考生和部署运维人员。管理、考试与在线练题使用同一套 Vue 前端、Node.js 后端、账号和登录态。

## 一 系统组成与访问入口

| 组件 | 技术与默认端口 | 用途 |
| --- | --- | --- |
| 统一前端 | Vue 3 + Vite，开发端口 `5173` | 管理、出题、考试与在线练题 |
| 后端服务 | Node.js + Express，默认端口 `3001` | REST API、鉴权、判分、报表、附件和练题服务 |
| 数据库 | MySQL 8，默认端口 `3306` | 业务数据与运行数据 |

生产环境使用一个入口，例如 `https://exam.example.com/`。在线练题路径为 `/exam/practice`。不要将 Node.js 的 `3001` 端口直接暴露到公网。

## 二 本地快速启动

### 2.1 环境要求

- Node.js `22.19+` 或 Node.js `24`
- npm
- MySQL 8

### 2.2 配置后端

复制 `server/.env.example` 为 `server/.env`，至少配置：

```ini
PORT=3001
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_NAME=enterprise_exam_system
DB_NAME_TEST=enterprise_exam_system_test
JWT_SECRET=请替换为至少32字节的随机字符串
STORAGE_DIR=storage/attachments
ENABLE_PRACTICE=true
PRACTICE_ONLY=false
PRACTICE_SESSION_SECRET=请使用独立随机字符串
PRACTICE_TZ_OFFSET=+08:00
```

`server/.env` 含数据库口令和签名密钥，不得提交到版本库。

### 2.3 安装依赖并初始化数据库

```powershell
npm install --ignore-scripts
npm --prefix server install --ignore-scripts
npm run db:init
```

`db:init` 会创建数据库、执行幂等结构升级并写入演示数据，可重复执行。`db:reset` 会清空并重建业务库，只能用于确认可丢弃数据的开发环境。

### 2.4 启动开发服务

分别打开两个终端：

```powershell
npm run dev:server
```

```powershell
npm run dev
```

访问：

- 系统登录：<http://localhost:5173/login>
- 在线练题：<http://localhost:5173/exam/practice>
- 后端健康检查：<http://localhost:3001/api/health>

## 四 使用说明

### 4.1 管理员首次配置顺序

1. 在“科室管理”中建立组织树。
2. 在“用户管理”中创建或导入用户，并分配角色与科室。
3. 在“菜单权限”中确认各角色可见菜单。
4. 在“系统设置”中配置考试、防作弊、账号安全、通知和品牌信息。
5. 在“题库管理”中创建题库并授权出题人。
6. 在“考试管理 → 新建考试”中，先填写考试设置、参与人员及可选的指定出题人，再直接从题库选题或抽题、调整分值，最后点击“创建考试”统一保存。
7. 指定出题人可在“考试管理”中维护被分配且具备题库权限的考试题目；到开始时间或已有作答后，题目与分值锁定。管理员仍可修改其他考务设置，不能通过后移开始时间解锁题目。
8. 在考试行操作中预览题目、导出考生版或答案版 PDF；不再提供独立试卷管理。
9. 在“练题端设置”中配置练题规则，并开放允许练习的题库。
10. 使用考生账号验收考试和在线练题完整流程。

已有环境升级考试管理结构且不希望恢复演示数据时，执行 `npm --prefix server run db:init -- --schema-only`。该命令不清空数据；历史共享试卷需先处理后才能添加一对一约束。

### 4.2 在线练题

考生登录主系统后，从“学习中心 → 在线练题”进入，可使用：

- 按题库练习、继续上次进度和每日一练
- 错题复习与连续答对自动移出
- 收藏题目
- 学习报告、连续打卡和成就徽章
- 公告与轮播内容

只有有效叶子题库、已开启练题且当前用户具有浏览权限时才会展示。管理员可单独关闭学习报告、错题本、收藏夹和成就入口。

## 六 Linux 生产部署

推荐拓扑：

```text
用户 -> exam.example.com -> Nginx -> /opt/enterprise-exam/current/web
                                  -> 127.0.0.1:3001 统一后端
统一后端 -> MySQL 8
```

1. 参考 `deploy/server.env.example` 创建 `/opt/enterprise-exam/shared/server.env`，确保 `ENABLE_PRACTICE=true`。
2. 安装 `deploy/systemd/enterprise-exam.service`，并让部署账号仅具有重启该服务的权限。
3. 使用 `deploy/nginx-exam.conf` 作为 Nginx 基线，替换域名并配置 TLS。
4. 将前端产物放在 `current/web`，后端产物放在 `current/server`。
5. 重启 `enterprise-exam`，验证 `/api/health` 后再开放流量。

仓库的 GitHub Actions 会把前端和后端两个产物打成一个发布包，通过 `deploy/remote-deploy.sh` 原子切换 `current` 软链接；探活失败时自动回滚到上一版本。

### 6.1 从旧独立练题端升级

旧环境曾部署 `enterprise-practice` 服务和独立练题域名。切换到本版本后应一次性执行：

1. 确认主服务 `server.env` 已设置 `ENABLE_PRACTICE=true`，并完成新版本部署与验收。
2. 停止并禁用 `enterprise-practice`，移除其 systemd unit。
3. 移除独立练题域名的 Nginx 站点并重新加载 Nginx。
4. 删除旧 `shared/practice.env`；确认无需回滚后再清理旧版本中的 `practice/` 静态产物。
5. 删除 GitHub Environment 中废弃的 `PRACTICE_SERVICE` 与 `PRACTICE_HEALTHCHECK_URL` 变量。

## 七 部署验收

### 7.1 接口与边界

```bash
curl -i https://exam.example.com/api/health
curl -i https://exam.example.com/api/practice/config
```

- 健康检查返回 `code=0` 和 `status=up`。
- 未登录访问练题业务接口返回统一鉴权错误。
- 外网无法直接访问 `3001`。
- 刷新 `/exam/practice` 仍由 SPA 正常接管，不返回 Nginx 404。

### 7.2 业务验收

- 管理员能开放题库并保存练题配置。
- 考生无需二次登录即可进入在线练题。
- 练题、错题本、收藏、学习报告和退出登录正常。
- 考试、管理和出题功能不受影响。
- 实时监控、Excel/PDF 导出和附件读写正常。

## 八 备份 升级与回滚

- 升级前备份数据库、`shared/server.env` 和附件目录。
- 执行前端与后端的 `npm ci`、测试和构建。
- 数据库升级必须使用幂等 `db:init`，不得在生产运行 `db:reset`。
- 代码回滚可切回保留的版本目录；数据库结构不会自动逆向回滚。

## 九 常见问题

### 页面刷新后返回 404

确认 Nginx 的 SPA 规则为 `try_files $uri $uri/ /index.html;`。

### 在线练题接口返回 404

确认统一后端环境中 `ENABLE_PRACTICE=true`，然后重启 `enterprise-exam`。

### 前端能打开但所有接口失败

确认 `/api/` 反向代理指向 `127.0.0.1:3001`，并检查后端日志和数据库连接。

### 部署后管理员无法登录或账号被锁定

先确认服务实际连接的数据库：`/opt/enterprise-exam/shared/server.env` 中的 `DB_NAME` 应与初始化时使用的库一致。`db:init` 是幂等操作，不会覆盖已有 `admin` 账号的密码；代码重新部署也不会把密码恢复为演示密码。

如果管理员密码已无法找回，可在服务器上使用应急恢复命令。该命令只接受管理员账号，密码从标准输入读取；执行后会更新密码、清除该账号的失败锁定、撤销旧会话并写入审计日志：

```bash
cd /opt/enterprise-exam/current/server
read -rsp '请输入新的管理员密码：' NEW_ADMIN_PASSWORD && echo
printf '%s' "$NEW_ADMIN_PASSWORD" | npm run admin:recover -- --username admin --password-stdin
unset NEW_ADMIN_PASSWORD
```

新密码必须符合“系统设置 → 账号安全”中的当前密码策略。无需重启后端，命令成功后即可重新登录。不要在生产环境运行 `db:reset`，它会清空业务数据。

### PDF 导出提示找不到字体

安装中文 TTF 字体并正确设置 `PDF_FONT_PATH`。
