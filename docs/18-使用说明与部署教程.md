# 企业内部在线考试系统使用说明与部署教程

本文面向系统管理员、出题人、考生和部署运维人员，覆盖本地启动、日常使用、生产部署、验收、升级与备份。系统由三个工程组成：内网管理与考试前端、Node.js 后端，以及可独立部署的公网练题前端。

## 一 系统组成与访问入口

| 组件 | 技术与默认端口 | 用途 |
| --- | --- | --- |
| 管理与考试前端 | Vue 3 + Vite，开发端口 `5173` | 管理员、出题人和考生使用 |
| 公网练题前端 | Vue 3 + Vite，开发端口 `5174` | 考生练题、错题本、收藏和学习报告 |
| 后端服务 | Node.js + Express，默认端口 `3001` | REST API、鉴权、判分、报表、附件和练题服务 |
| 数据库 | MySQL 8，默认端口 `3306` | 业务数据与运行数据 |

生产环境建议使用两个域名：

- 内网考试端：`https://exam.example.com/`
- 公网练题端：`https://practice.example.com/practice/`

公网练题端推荐连接独立的 `PRACTICE_ONLY=true` 后端实例，并使用最小权限数据库账号。不要将 Node.js 的 `3001` 或 `3002` 端口直接暴露到公网。

## 二 本地快速启动

### 2.1 环境要求

- Node.js `22.19+` 或 Node.js `24`
- npm
- MySQL 8
- Windows PowerShell、Linux 或 macOS 终端

### 2.2 配置后端

在项目根目录执行：

```powershell
Copy-Item server\.env.example server\.env
```

编辑 `server/.env`，至少填写以下内容：

```ini
PORT=3001
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_NAME=enterprise_exam_system
DB_NAME_TEST=enterprise_exam_system_test
JWT_SECRET=请替换为至少32字节的随机字符串
STORAGE_DIR=storage/attachments
ENABLE_PRACTICE=true
PRACTICE_ONLY=false
PRACTICE_JWT_SECRET=请使用不同于JWT_SECRET的随机字符串
PRACTICE_SESSION_SECRET=请使用另一个随机字符串
PRACTICE_TZ_OFFSET=+08:00
```

`server/.env` 含数据库口令和签名密钥，不得提交到版本库或发送到聊天群。

### 2.3 安装依赖并初始化数据库

```powershell
npm install --ignore-scripts
npm --prefix server install --ignore-scripts
npm --prefix practice-web install --ignore-scripts
npm run db:init
```

`db:init` 会创建数据库、执行幂等结构升级并写入演示数据，可重复执行。`db:reset` 会清空并重建业务库，只能用于确认可丢弃数据的开发环境。

### 2.4 启动三个开发服务

分别打开三个终端：

```powershell
npm run dev:server
```

```powershell
npm run dev
```

```powershell
npm --prefix practice-web run dev
```

访问地址：

- 管理与考试端：<http://localhost:5173/login>
- 公网练题端：<http://localhost:5174/practice>
- 后端健康检查：<http://localhost:3001/api/health>

健康检查正常时返回 `code=0`，并在 `data` 中包含 `status: "up"`。

## 四 使用说明

### 4.1 管理员首次配置顺序

建议按以下顺序完成上线配置，避免出现用户无科室、出题人无题库权限或考试无可用试卷的问题：

1. 在“科室管理”中建立组织树。
2. 在“用户管理”中创建用户或通过 Excel 批量导入用户，并分配角色与科室。
3. 在“菜单权限”中确认各角色可见的菜单。
4. 在“系统设置”中配置考试默认值、防作弊、账号安全、通知、归档和品牌信息。
5. 在“题库管理”中创建题库，并给出题人授权。
6. 在“试卷管理”中完成组卷与预览。
7. 在“考试管理”中绑定试卷、选择科室、设置时间窗、时长、及格线和作答次数后发布。
8. 用考生账号验证考试可见性、答题、交卷、成绩和通知流程。

### 4.2 题库与试题

管理员和被授权的出题人可以创建题库、维护试题、复制题库和按条件筛选题目。系统支持单选、多选、判断、填空和简答题。

Excel 导入操作：

1. 进入“题库管理”，打开目标题库。
2. 点击“批量导入试题”，先下载系统模板。
3. 按模板的 12 列表头填写数据，不要修改列名。
4. 上传 `.xlsx` 文件并查看预校验结果。
5. 处理错误行；科目与题库分类不一致属于警告，不会自动阻断导入。
6. 确认导入，必要时导出错误报告。

默认限制为单文件不超过 `5 MB`、单次不超过 `2000` 行，可由管理员在系统设置中调整。开启“跳过重复题目”后，系统按题型、题干、选项和答案的内容指纹复用已有题目。

### 4.3 组卷与发布考试

在“试卷管理”中可使用两种组卷方式：

- 按题型抽题：设置各题型数量和分值；题量不足时系统会提示缺口并阻止保存。
- 手动选题：从一个或多个题库勾选试题，再逐题调整分值和顺序。

试卷保存后先预览并核对总分，再由管理员进入“考试管理”发布考试。考试开始时会冻结试卷快照，因此之后修改题库或试卷不会改变已经生成的答卷。

已产生成绩记录的考试不能直接删除。需要临时照顾个别考生时，使用特殊考试安排增加时长、额外次数或设置免考，不要直接修改全体考试规则。

### 4.4 监考 阅卷与成绩

- “实时考试监控”显示考生状态、进度和剩余时间，支持加时与强制交卷。
- 客观题交卷后自动判分；含简答题的答卷进入“人工阅卷”。
- “成绩报表”可查看分数段、科室对比、错题排行和切屏记录，并导出 Excel 或 PDF。
- 考生提出补考或成绩复核后，管理员分别在“补考管理”和“成绩复核”中处理。
- 关键写操作进入“审计日志”，登录行为进入“登录日志”。

### 4.5 考生参加考试

1. 登录后在“首页”或“我的考试”查看待考和进行中的考试。
2. 在允许的时间窗内点击开始考试。中途退出后再次进入会恢复同一次答题记录。
3. 答题页会自动暂存答案；仍建议保持网络稳定，不要多设备同时作答。
4. 倒计时结束时系统自动交卷，也可提前手动交卷。
5. 在“我的成绩”查看客观题结果、解析和最终成绩；简答题需等待人工阅卷。
6. 符合规则时，可在“我的补考”申请补考；启用成绩复核后可按规定提交复核申请。

答题页可能启用水印、禁止复制和切屏记录。关闭浏览器、断网或切换页面不会停止服务端计时。

### 4.6 公网练题

管理员先在“练题端设置”中开启练题功能、配置题量与答案展示规则，并将允许公开练习的题库打开“对外开放”。考生使用自己的考生账号登录练题端，可使用以下功能：

- 按题库练习或继续上次进度
- 每日一练
- 错题复习和连续答对自动移出
- 收藏题目
- 学习报告、连续打卡和成就徽章
- 查看公告与轮播内容

题库没有开启“对外开放”时不会出现在练题端。学习报告、错题本、收藏夹和成就入口也可能被管理员单独关闭。

## 五 上线前检查与构建

### 5.1 执行质量检查

```bash
npm ci
npm test
npm run build

npm --prefix server ci
npm --prefix server run test
npm --prefix server run build

npm --prefix practice-web ci
npm --prefix practice-web run test
npm --prefix practice-web run build
```

构建产物：

- 管理与考试前端：`dist/`
- 公网练题前端：`practice-web/dist/`
- 后端：`server/dist/`

PDF 导出依赖支持中文的 TTF 字体。Linux 生产环境应安装中文字体，并通过 `PDF_FONT_PATH` 指向该字体文件。

### 5.2 推荐生产拓扑

```text
内网用户 -> exam.example.com -> Nginx -> 管理考试静态文件
                                      -> 127.0.0.1:3001 完整后端

公网用户 -> practice.example.com -> Nginx -> 练题静态文件
                                          -> 127.0.0.1:3002 练题专用后端

完整后端与练题专用后端 -> 同一 MySQL 8 数据库
练题专用后端           -> practice_app 最小权限账号
```

双实例方案的核心价值是：公网进程在 `PRACTICE_ONLY=true` 时根本不注册考试、用户、报表和管理接口；即使反向代理配置失误，这些路由也不可用。

## 六 Linux 生产部署

以下示例假定代码位于 `/opt/enterprise-exam`，服务账号为 `examapp`。命令需要按实际 Linux 发行版和组织权限策略调整。

### 6.1 准备目录与软件

安装 Node.js 24、MySQL 8、Nginx 和中文字体，并创建不可交互登录的服务账号。确认：

```bash
node --version
npm --version
mysql --version
nginx -v
```

将项目放入 `/opt/enterprise-exam`，让 `examapp` 对 `server/storage` 有写权限。数据库文件、附件目录和 `.env` 不应放入 Web 静态目录。

### 6.2 初始化数据库

先复制环境变量模板：

```bash
cd /opt/enterprise-exam
cp server/.env.example server/.env
chmod 600 server/.env
```

首次初始化时，`server/.env` 中的数据库账号需要具有建库、建表和结构升级权限：

```bash
npm --prefix server ci
npm run db:init
```

初始化完成后，生产运行账号建议只保留业务所需权限。后续版本升级如包含数据库结构变更，应先备份，再临时使用迁移账号执行 `npm run db:init`，完成后恢复运行账号。

例如，数据库与应用位于同一主机时，可由数据库管理员创建日常运行账号：

```sql
CREATE USER IF NOT EXISTS 'exam_app'@'127.0.0.1' IDENTIFIED BY '替换为运行账号强口令';
GRANT SELECT, INSERT, UPDATE, DELETE
  ON `enterprise_exam_system`.* TO 'exam_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

创建后将 `server/.env` 的 `DB_USER` 和 `DB_PASSWORD` 改为该账号。若数据库不在本机，应由数据库管理员将主机范围改为应用服务器的固定地址，不要为了省事长期使用 `%` 或 root。

公网练题最小权限账号使用仓库脚本创建：

```bash
# 先将脚本中的 <PRACTICE_DB_PASSWORD> 替换为强口令
mysql -u root -p < deploy/db-grants-practice.sql
```

该脚本会限制练题实例只读用户、科室、题库和内容数据，并仅允许写入练题进度、错题、收藏、打卡及触达回执等必要表。

### 6.3 配置完整后端

生产 `server/.env` 示例：

```ini
NODE_ENV=production
PORT=3001
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=exam_app
DB_PASSWORD=替换为运行账号强口令
DB_NAME=enterprise_exam_system
DB_NAME_TEST=enterprise_exam_system_test
JWT_SECRET=替换为随机密钥
JWT_EXPIRES_IN=12h
STORAGE_DIR=storage/attachments
PDF_FONT_PATH=/usr/share/fonts/truetype/你的中文字体.ttf
ENABLE_PRACTICE=false
PRACTICE_ONLY=false
PRACTICE_TZ_OFFSET=+08:00
```

可用以下命令生成密钥：

```bash
openssl rand -hex 32
```

### 6.4 配置练题专用后端

创建 `/etc/enterprise-exam/practice.env`，权限设为 `600`：

```ini
NODE_ENV=production
PORT=3002
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=practice_app
DB_PASSWORD=替换为练题账号强口令
DB_NAME=enterprise_exam_system
DB_NAME_TEST=enterprise_exam_system_test
JWT_SECRET=替换为独立随机密钥
ENABLE_PRACTICE=true
PRACTICE_ONLY=true
PRACTICE_JWT_SECRET=替换为独立随机密钥
PRACTICE_SESSION_SECRET=替换为另一个独立随机密钥
PRACTICE_JWT_EXPIRES_IN=12h
PRACTICE_SESSION_TTL=1800
PRACTICE_TZ_OFFSET=+08:00
```

不要只填写注释中的 `PRACTICE_DB_USER`；当前服务实际读取的数据库连接变量是 `DB_USER` 和 `DB_PASSWORD`。

### 6.5 安装依赖并构建

```bash
cd /opt/enterprise-exam
npm ci
npm --prefix server ci
npm --prefix practice-web ci
npm run build
npm --prefix server run build
npm --prefix practice-web run build
mkdir -p server/storage/attachments
```

确认 `examapp` 对 `server/storage/attachments` 可写，并保留三个 `package-lock.json`，以保证升级时依赖可复现。

### 6.6 使用 systemd 托管后端

创建 `/etc/systemd/system/enterprise-exam.service`：

```ini
[Unit]
Description=Enterprise Exam API
After=network.target mysql.service

[Service]
Type=simple
User=examapp
Group=examapp
WorkingDirectory=/opt/enterprise-exam/server
EnvironmentFile=/opt/enterprise-exam/server/.env
ExecStart=/usr/bin/node dist/index.js
Restart=on-failure
RestartSec=5
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

创建 `/etc/systemd/system/enterprise-practice.service`：

```ini
[Unit]
Description=Enterprise Exam Practice-only API
After=network.target mysql.service

[Service]
Type=simple
User=examapp
Group=examapp
WorkingDirectory=/opt/enterprise-exam/server
EnvironmentFile=/etc/enterprise-exam/practice.env
ExecStart=/usr/bin/node dist/index.js
Restart=on-failure
RestartSec=5
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

启用并检查服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now enterprise-exam enterprise-practice
sudo systemctl status enterprise-exam enterprise-practice
curl http://127.0.0.1:3001/api/health
curl http://127.0.0.1:3002/api/health
```

### 6.7 配置内网考试端 Nginx

以下为 HTTP 内网示例；如跨不可信网络访问，应增加组织证书或 TLS：

```nginx
server {
    listen 80;
    server_name exam.example.com;

    root /opt/enterprise-exam/dist;
    index index.html;
    client_max_body_size 10m;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 1h;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`proxy_buffering off` 和较长的读取超时用于保障实时监考 SSE 推送；推送不可用时前端会自动回退到轮询。

### 6.8 配置公网练题端 Nginx

仓库提供 `deploy/nginx-practice.conf` 作为安全基线，部署时必须替换域名、证书路径和静态目录，并将上游端口改为练题专用实例的 `3002`。

当前练题构建产物使用根路径 `/assets/`，因此建议为练题端使用独立域名，并在 HTTPS `server` 块中确保包含以下静态资源规则：

```nginx
root /opt/enterprise-exam/practice-web/dist;

location = / {
    return 302 /practice/;
}

location = /practice {
    return 302 /practice/;
}

location /practice/ {
    try_files $uri $uri/ /index.html;
}

location /assets/ {
    try_files $uri =404;
    expires 7d;
    add_header Cache-Control "public, immutable";
}
```

练题 API 只允许以下入口：

```nginx
location = /api/health {
    proxy_pass http://127.0.0.1:3002/api/health;
}

location /api/practice/ {
    proxy_pass http://127.0.0.1:3002;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /api/ {
    return 404;
}
```

公网配置还应保留仓库模板中的 HTTPS、HSTS、连接数限制和登录接口独立限流。不要在同一个练题域名根路径部署其他使用 `/assets/` 的前端，否则静态资源路径会冲突。

检查并加载配置：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 七 部署验收

### 7.1 接口与安全边界

```bash
curl -i https://exam.example.com/api/health
curl -i https://practice.example.com/api/health
curl -i https://practice.example.com/api/practice/config
curl -i https://practice.example.com/api/users
```

预期结果：

- 两个健康检查均成功。
- 未登录访问受保护练题接口返回未授权，而不是服务器错误。
- 公网访问 `/api/users` 返回 `404`。
- 直接从外网访问 `3001`、`3002` 均失败。

### 7.2 业务验收

1. 管理员能登录、创建科室和用户。
2. 出题人只能看到已授权题库，并能建题和组卷。
3. 管理员能发布一场短时测试考试。
4. 考生能开考、暂存、交卷并看到成绩。
5. 含简答题的答卷能进入人工阅卷并完成计分。
6. 监考页面能收到实时状态；断开 SSE 后能回退轮询。
7. 练题端只显示已开放题库，错题、收藏和报告可正常使用。
8. Excel 和 PDF 导出中文显示正常。
9. 上传的富文本图片在重新登录后仍可访问。
10. 审计日志与登录日志能查询到刚才的操作。

## 八 备份 升级与回滚

### 8.1 备份

至少备份两部分：MySQL 数据库和 `server/storage` 附件目录。

```bash
mysqldump --single-transaction --routines --triggers enterprise_exam_system > enterprise_exam_system.sql
tar -czf enterprise_exam_storage.tar.gz -C /opt/enterprise-exam/server storage
```

备份文件应加密并存储到另一台主机或对象存储中，定期做恢复演练。仅备份数据库会丢失简答题和公告中上传的图片。

### 8.2 升级

1. 记录当前版本并备份数据库和附件。
2. 拉取经过测试的发布版本。
3. 执行三个工程的 `npm ci`、测试与构建。
4. 使用迁移账号执行 `npm run db:init`；不要在生产执行 `db:reset`。
5. 重启两个后端服务并重新加载 Nginx。
6. 执行健康检查和关键业务冒烟测试。

```bash
sudo systemctl restart enterprise-exam enterprise-practice
sudo systemctl reload nginx
journalctl -u enterprise-exam -u enterprise-practice -n 200 --no-pager
```

若升级失败，应先停止写入流量，再恢复数据库、附件和上一版本构建产物。只回滚代码而不回滚不兼容的数据库结构可能造成二次故障。

## 九 常见问题

### 后端提示缺少环境变量

确认运行进程实际读取了 `server/.env` 或对应的 systemd `EnvironmentFile`，并检查 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME` 和 `JWT_SECRET` 均非空。

### 页面刷新后返回 404

Vue Router 使用 history 模式。Nginx 静态站点必须配置 `try_files ... /index.html`，不能只提供静态文件目录。

### 前端能打开但所有接口失败

检查浏览器请求是否访问同源 `/api/**`，再检查 Nginx `proxy_pass`、后端端口、服务日志和数据库连通性。生产前端不依赖 Vite 开发代理。

### 练题页样式或脚本 404

练题构建默认从 `/assets/` 加载资源。使用独立练题域名，并确认 Nginx 的 `root` 指向 `practice-web/dist` 且配置了 `/assets/`。

### PDF 导出提示找不到字体

安装支持中文的 `.ttf` 字体，并在后端运行环境中设置 `PDF_FONT_PATH` 为字体的绝对路径，然后重启后端。

### 实时监考频繁回退轮询

确认 Nginx 未缓冲 SSE、读取超时足够长，并检查代理或负载均衡设备是否主动关闭长连接。

### 上传附件后无法显示

确认 `STORAGE_DIR` 指向持久化目录、服务账号有写权限，并且升级或迁移时同步了整个 `server/storage` 目录。
