## 2. ② U2 两步验证增强（恢复码 + 管理员强制重置）

### 2.1 恢复码

- 新表 `user_recovery_codes`（仅存 **bcrypt 哈希**，一次性使用；用后即标记失效）。
- `utils/recoveryCode.ts`（零依赖）：字符集 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（**31 位，排除 0/O/1/I/L** 等易混字符），格式 `XXXXX-XXXXX`，默认一次生成 **10 个**。
- 归一化：大小写不敏感、忽略 `-` 与空格（`normalizeRecoveryCode`）；`isRecoveryCodeFormat` 与字符集**严格一致**。
- `POST /api/auth/2fa/recovery-codes`（登录用户，需**密码 + 当前 2FA 验证码**）：重新生成 → **作废旧码**、返回明文仅此一次。
- `verifyTwoFactor` 扩展：登录第二阶段可输入动态码**或**恢复码；命中恢复码即消费该条。
- 通知：新增事件模板 `twoFactorReset`（`security` 分类，默认标题「两步验证已被重置」）；通知事件总数 8 → **9**。

### 2.2 管理员强制重置

- `POST /api/users/:id/2fa/reset`（admin）：清空目标用户 `two_factor_secret` / `two_factor_enabled`、**作废全部恢复码**、**撤销其全部登录会话**，并**通知本人**。
- `auth.service.ts` 新增 `accountSecurityPolicy` / `adminResetTwoFactor` / `issueRecoveryCodes` / `regenerateRecoveryCodes`。
- 审计动作新增 `user.two_factor_reset`（目标类型 `user`）。

## 3. ③ U3 归档自动定时任务

- `maintenance.service.archive(input, actor: { id, name? }, extraDetail = {})`：签名由 `operatorId: string` 改为 **actor 对象**（为系统 actor 保留名称）。
- 系统 actor：`SYSTEM_ACTOR = { id: 'system', name: '系统自动' }`；自动归档的审计 detail 带 `auto: true`。
- 调度：`startArchiveScheduler()` 使用 `setInterval(..., 60_000).unref()`（**不阻塞进程退出**），在 `index.ts` 的 `app.listen` 之后启动。
- 三条防重保险：**单飞**（`running` 标志，执行中跳过本轮）、**同日去重**（`lastAutoDate` 以本地日期为键，每天最多一次）、`lastAutoRun` 记录时间供前端展示。

- 新接口 `POST /api/maintenance/archive/auto-run`（admin）：**立即执行一次**自动归档策略（走同一套去重逻辑，受 `running` 保护）。

## 4. ① U1 监考大屏 SSE 实时推送

### 4.1 服务端连接中心

- 新 `modules/exams/examMonitor.stream.ts`：**按考试聚合**的订阅中心，`Map<examId, Set<SseSink>>`。
- **共享 ticker**：每场考试**每轮只查库一次**再广播给该场全部订阅者 → N 个监考页共享 1 次数据库查询（这是「降低数据库压力」的关键）。
- 心跳：每 **15s** 下发 SSE 注释帧（`: ping`），防中间代理断连；`setInterval(...).unref()`。
- 容量上限：单场 **20**（`MAX_CLIENTS_PER_EXAM`）、全局 **200**（`MAX_CLIENTS_TOTAL`）。
- 失败下发 `error` 事件但**保留连接**（不静默断）。
- `resetMonitorStream()` 供测试复位。

### 4.2 接口

- `GET /api/exams/:id/monitor/stream`（admin）→ `text/event-stream`。
- 响应头：`Cache-Control: no-cache, no-transform` + `Connection: keep-alive` + `X-Accel-Buffering: no`（关 Nginx 缓冲）。
- 连接保活：`res.setTimeout(0)` + `req.socket.setTimeout(0)` + `setNoDelay(true)`。
- 帧序：连上先发 **`ready`**（`MonitorStreamInfoDto`，含推送间隔等）→ 再发首帧 **`monitor`**（`ExamMonitorDto` 快照）。
- **开关关闭 / 超限 / 考试不存在均写在 SSE 头之前**，返回普通 JSON，便于前端干净降级。
- `close` / `error` → `removeClient`。
- 新错误码 `MONITOR_PUSH_DISABLED: 1016`（HTTP 503）+ 便捷构造 `monitorPushDisabled()`。

### 4.3 前端

- 新 `src/utils/monitorStream.ts`：**fetch + ReadableStream** 手写 SSE 解析。
  > 原因：鉴权仅走 `Authorization: Bearer`（header），原生 `EventSource` **无法带 header**，服务端也不提供 `?token=` 兜底 → 只能 fetch 流式读取。
- 指数退避重连 1s → 2s → 4s … 上限 **30s**（成功后复位）；`1016 / 401 / 403` 判定为**永久不可用** → 不再重连；`close()` 后彻底停止。
- `ExamMonitorPage.vue`：默认走推送；不可用时**自动回退 15s 轮询**；顶部「刷新方式」徽标三态：`实时推送 · 每 N 秒` / `推送重连中 · 已降级轮询 15 秒` / `轮询 · 每 15 秒`。
- 新设置：`monitorPushEnabled`（默认 **true**；定位为「降级闸门」，因前端恒有轮询兜底）/ `monitorPushIntervalSeconds`（默认 5，3~60）→ 在「设置 → 考试规则」可调。

## 5. ④ U4 富文本附件对象存储

### 5.1 存储抽象

- 新 `utils/attachmentStore.ts`：`AttachmentStore` 接口（`save / read / createStream / exists / remove`）+ **本地磁盘实现** + 单例 `attachmentStore` —— 即「将来换云对象存储」的**唯一替换点**。
- 落盘路径：`<STORAGE_DIR>/yyyy/MM/<id>.<ext>`；`STORAGE_DIR` 默认 `storage/attachments`，**相对路径以 server 根目录为锚点**（`config/env.ts` 的 `serverRoot` 改为 `export const`）。
- 文件名**服务端生成**；`isSafeStorageKey()` 以 `^\d{4}/\d{2}/[A-Za-z0-9_-]+\.[a-z0-9]{2,5}$` 强校验，**杜绝路径穿越**。
- 类型白名单：`image/png` / `image/jpeg` / `image/gif` / `image/webp` / `image/bmp`。
- 新表 `attachments`（`id / owner_id / kind / mime / size / storage_key / created_at`，2 个索引，无外键；**不做 ref_count**）。

### 5.2 接口与双通道鉴权

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/attachments` | `authRequired` | multipart 字段 `file`；multer **按设置每次请求动态构造**（尊重当前上限改动） |
| GET | `/api/attachments/:id` | `authOptional` | 流式返回图片 |

- **关键设计：签名 URL。** 富文本经 `v-html` 渲染，浏览器 `<img>` **不能带 Authorization 头**，仅 Bearer 会导致**全部裂图**。故上传返回的 URL 带 `?t=<HMAC_SHA256(JWT_SECRET, 'attachment:' + id) 前 32 hex>`。
- 读取放行条件（二者其一）：**合法 Bearer 且为本人 / `admin` / `author`**，**或** **合法签名**；签名用 `timingSafeEqual` 比较。
- 读前先 `exists()`，避免发出半截流式响应。
- 新增中间件 `authOptional`（有 Bearer 就解析、无则静默放行）；`authRequired` 重构为复用新抽出的 `resolveUser()`。

### 5.3 净化与前端

- `sanitizeRichText` 的 `img[src]` 白名单由「仅 data URI」扩为「**data URI + 站内 `/api/attachments/<id>?t=`**」；`ATTACHMENT_IMAGE_RE` 严格锚定前缀 → `//evil.com`、`/uploads/x.png`、`../` 全部拒绝。
- `records.service.saveAnswers` 按设置传 `richTextOptions = { maxImages, maxImageBytes }`。
- 前端：新 `src/api/attachments.ts`（复用 `http.upload`）；`RichTextEditor.vue` 改为**上传后回填站内 URL**（去掉 FileReader/dataURI）+ **Ctrl+V 粘贴图片** + 上传中态 + URL 属性转义；`QuestionCard.vue` 从 settings store 注入上限。
- 新设置：`richTextImageMaxMb`（默认 2，1~10）/ `richTextImageMaxCount`（默认 3，1~10）。
- `.gitignore` 加 `server/storage`；`.env.example` 加 `STORAGE_DIR`。
- **`express.json` 仍保持 8mb**：兼容存量内联 base64 作答（不因新通道而收紧）。

## 6. ⑤ U5 题库 / 导入内容去重复用

### 6.1 内容指纹

- 新 `utils/questionFingerprint.ts`（零依赖）：指纹 = **题型 + 规范化题干 + 规范化选项 + 规范化答案** → sha256 取**前 40 位 hex**。
- 规范化：文本折叠空白 + trim；**客观题（纯数值）答案排序**（等价序列视为同一题）、**填空 / 简答保持原序**（空位有语义）；字段间以 `\u0001` 分隔防拼接歧义。

### 6.2 落地方式

- **`cloneBank`（题库复制）**：同批内指纹相同 → **复用首个新建的题目 id，不重复建行**；返回类型由 `BankDto` 改为 **`BankCloneResultDto { bank, copied, reused }`**（**破坏性变更**，前端与 v17e 断言已同步改 `data.bank.*`）；审计 detail 增 `reused`。
- **Excel 导入**：`POST /api/questions/import/commit` 增可选 `dedupe`（**默认 false = 行为完全不变**）；开启时按目标题库既有题目指纹去重，命中跳过并计入 `reused`；`CommitResult` 增 `reused`（`successCount + reused + failCount === totalRows`）。
- 前端：`BankCloneDialog.vue` 反馈「新建题目 N 道，内容重复复用 M 道」；`QuestionImportDialog.vue` 增「跳过重复题目（内容去重）」开关 + 完成页计数。

### 6.3 关键结论（范围澄清）

> **无引用表时，「跨库共享同一条题目行」不可实现。** 题目归属由 `questions.bank_id` 单列决定，题库列表 / 组卷 / 统计**全部按该列过滤**，同一行无法同时属于两个库。
>
> 故 U5「跨库题目引用共享」**落地为「题目写入题库的路径上按内容指纹去重，同内容只保留一行」**（即用户拍板的「内容去重式复用」）。若将来确实要「一题多库引用」，需回到 `bank_question_refs` 引用表 + 删除保护 + 统计口径拆分——属结构级改造，不在 v1.8 范围。

## 11. 部署与升级步骤

1. **拉取代码**：切到 v1.8 提交（`a2ca84f` 或其后）。
2. **安装依赖**：v1.8 **未新增第三方运行时依赖**（SSE 解析、恢复码、调度器、内容指纹均零依赖自研）：
   ```bash
   npm install --ignore-scripts
   npm --prefix server install --ignore-scripts
   ```
3. **数据库升级**（幂等，直接对现有库执行即可，无需重建）：
   ```bash
   npm run db:init
   ```
   升级内容：建 `user_recovery_codes`（恢复码）与 `attachments`（附件元数据）。
4. **配置环境变量**（可选，均有默认值）：新增 `STORAGE_DIR`（默认 `storage/attachments`）。
   > 相对路径以 **server 根目录**为锚点；生产环境建议指向**持久化卷**（容器部署务必挂载，否则重启丢图）。
5. **目录权限**：确保 Node 进程对 `STORAGE_DIR` 有**读写**权限（首次上传会自动创建 `yyyy/MM` 子目录）。
6. **构建前端**：`npm run build`（产物 `dist/`）。
7. **反向代理（重要）**：SSE 走 Nginx 时需关闭响应缓冲 —— 服务端已下发 `X-Accel-Buffering: no`；若代理另有 `proxy_buffering on` 覆盖，请在该 location 显式设 `proxy_buffering off; proxy_read_timeout 3600s;`。
8. **冒烟建议**：
   - **②** 在「账号安全」生成恢复码 → 退出登录走 2FA 输入恢复码登录成功、该码再用失败；管理员在用户管理对其「重置两步验证」→ 本人收到通知且后台可重新绑定。
   - **③** 打开「系统维护」→ 点「立即执行一次自动归档」→ 查看归档量与审计记录（actor 显示「系统自动」）。
   - **①** 考试进行中打开「监控」大屏 → 顶部徽标显示「实时推送 · 每 N 秒」；在设置里关掉推送开关 → 再开页面自动降级为「轮询 · 每 15 秒」。
   - **④** 简答作答中 **Ctrl+V 粘贴截图** → 上传成功后图片正常显示；查看答案原文应含 `/api/attachments/<id>?t=...` 而**非** `data:image/...`。
   - **⑤** 复制题库 → 对话框显示「新建 N 道，内容重复复用 M 道」；Excel 导入勾选「跳过重复题目」→ 完成页体现复用条数。
   > 该链路已固化为自动化测试（`v18a`–`v18e` + `e2e.*`），执行 `npm --prefix server run test` 即可回归。

## 12. 已知限制与注意事项

- **SSE 连接中心为进程内状态**：多实例部署时各实例**各自维护订阅**——推送结果正确，但**容量计数非全局**（全局上限只在单实例内生效）。
- **推送依赖长连接**：经过会缓冲响应的中间代理时可能被「攒批」，须确保 `proxy_buffering off`（服务端已发 `X-Accel-Buffering: no`）；另有 15s 心跳与前端自动降级轮询兜底，最坏情况等价于 v1.7 行为。
- **前端 SSE 为自研解析**：因鉴权只走 Bearer header，未使用原生 `EventSource`；服务端也**不提供 `?token=` 兜底**（避免 token 落日志）。
- **附件为单机本地存储**：多实例需**共享存储**或替换 `AttachmentStore` 为云实现（接口已就位，替换点唯一）。
- **孤儿附件未清理**：作答被覆盖 / 记录删除后，磁盘上的图片**不会自动回收**，需后续加清理任务。
- **恢复码仅存哈希**：生成后**只显示一次**，丢失只能重新生成（重新生成会作废旧码）。
- **强制重置会撤销会话**：管理员重置 2FA 时目标用户**全端下线**，需重新登录并重新绑定。
- **`BankCloneResultDto` 为破坏性契约变更**：如有外部调用方依赖 `BankClone` 直接返回 `BankDto`，需同步改为 `data.bank.*`。
- **导入去重默认关闭**：`dedupe` 默认 `false`，保持历史行为不变；如需去重需显式勾选（或调用方显式传参）。
- **`express.json` 仍为 8mb**：存量内联 base64 作答仍可提交；新作答建议走附件通道（请求体更小）。
- **红线**：所有脚本/测试仅针对 `enterprise_exam_system`（及测试库 `enterprise_exam_system_test`）；**严禁**操作同实例下的其他库（如 `exam_system`）。
