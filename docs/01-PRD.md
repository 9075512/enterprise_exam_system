## 1. 项目信息

- **Language**：简体中文
- **Programming Language**：Vite + React + MUI + Tailwind CSS（前端默认技术栈，最终由架构师确认）
- **Project Name**：enterprise_exam_system
- **原始需求复述**：开发一个企业内部用的在线考试系统，支持试题管理（单选/多选/判断三种题型）、题库组卷、考试安排发布、在线答题自动判分、成绩统计报表、分科室考试（科室隔离）、三种角色权限控制（管理员/出题人/考生）、防作弊机制（限时交卷、切屏检测），界面简洁，适配桌面端浏览器。

## 2. 产品定义

### 2.1 产品目标

1. **高效考试组织**：管理员与出题人能够在 30 分钟内完成"录题 → 组卷 → 发布考试"全流程，替代线下纸质考试的组织成本。
2. **准确自动判分**：客观题（单选/多选/判断）100% 自动判分，交卷后考生立即查看成绩，消除人工阅卷。
3. **数据驱动管理**：提供成绩统计与分析报表（按考试/按科室/按个人），让管理者可量化员工知识水平。
4. **可控的考试秩序**：通过限时、切屏检测、科室隔离等机制，保证考试过程基本可信、数据互不可见。

### 2.2 用户故事

**管理员**
- 作为管理员，我想通过账号+密码登录系统并进入管理后台，以便对全系统进行管理。
- 作为管理员，我想维护科室和用户账号（创建/编辑/停用），以便考生登录后自动归属到正确的科室。
- 作为管理员，我想创建/编辑/删除考试并指定"考试时间窗、时长、参与科室、关联试卷"，以便向目标科室定向发布考试。
- 作为管理员，我想查看所有考试的成绩统计与分析报表（平均分、及格率、分数段分布、科室对比、错题率排行），以便量化各部门掌握情况。

**出题人**
- 作为出题人，我想在题库中新增/编辑/删除/批量导入试题（单选、多选、判断，含题干、选项、正确答案、解析、所属科目/标签），以便沉淀企业题库资产。
- 作为出题人，我想从题库中筛选、挑选题目并设置每题分值，组成一份试卷（支持预览总卷面分），以便为考试提供标准化试卷。
- 作为出题人，我想只管理自己负责科目下的试题与试卷，以便职责边界清晰（权限由管理员分配）。

**考生**
- 作为考生，我想登录后只看到"本科室可参加且在时间窗内"的考试列表，以便不被无关考试干扰、也不可见他科室考试。
- 作为考生，我想点击"开始考试"进入答题页，页面倒计时结束自动交卷，以便在规定时长内完成答题。
- 作为考生，我想在答题页对单选/多选/判断题作答，并支持暂存答案、上一题/下一题跳转，以便灵活答题不丢进度。
- 作为考生，我想交卷后立即看到客观题得分和成绩明细，以便及时了解自己的掌握程度。
- 作为考生，我想查看自己的历史考试成绩列表，以便追踪个人学习情况。

**防作弊（考生/管理员共同场景）**
- 作为管理员，我希望考生答题时切出浏览器标签页/窗口即被系统检测并记录（切屏次数、离开时长），以便事后审查作弊嫌疑。
- 作为考生，我理解切屏行为会被记录并可能在报告中标记，以便公平参加考试。

## 3. 技术规范

### 3.1 需求池（本版本范围）

#### P0 — Must have（本期必须实现）

| # | 模块 | 需求 |
|---|------|------|
| P0-1 | 认证与角色 | 账号密码登录；三种角色：管理员、出题人、考生；基于角色的菜单与接口权限控制 |
| P0-2 | 组织管理 | 管理员维护科室（增删改查）与用户账号（增删改查、重置密码、账号↔科室归属） |
| P0-3 | 试题管理 | 出题人录入/编辑/删除/查询试题；支持单选、多选、判断三种题型；字段含题干、选项、正确答案、分值、所属科目分类 |

| P0-5 | 考试管理 | 管理员创建考试：关联试卷、设置开始/截止时间、考试时长、参与科室（可多选）、及格分数线 |

| P0-8 | 自动判分 | 交卷后即时判分：单选/判断全对得分，多选全对得分（见"待确认问题"Q3 的少选规则），生成成绩记录 |
| P0-9 | 成绩查询 | 考生查看本人成绩；管理员查看某场考试全部成绩列表 |
| P0-10 | 防作弊 | 限时交卷（时长到强制提交）；切屏检测（监听 visibilitychange，记录切屏次数与离开时长，交卷后随成绩展示给管理员） |

### 3.3 待确认问题（Open Questions）

> 以下为产品侧已做合理假设的决策点，请主理人转达用户确认，不阻塞开发：

1. **多选题判分规则**（假设：多选必须完全选对才得分，漏选/错选均 0 分）。是否需要"少选按比例给分"？
2. **切屏处理策略**（假设：仅记录次数与时长并在报表中展示，不强制交卷）。是否需要"切屏 N 次自动强制交卷"？N 值多少？
3. **账号创建方式**（假设：管理员在后台手动创建账号并分配科室与角色，无自助注册、无邮箱验证）。是否符合企业现状？若人数多是否需要批量导入账号？
4. **考试资格与重复考试**（原假设：一场考试每位考生只能考一次，错过时间窗视为缺考）。**【已由增量 v1.3 取代】** 已确认支持可配置的「答题次数」上限（1–10，默认 1）实现多次作答，未交卷可「继续考试」续考（续考不消耗次数），报表按每人最后一次已交卷记录统计；详见 `docs/03-PRD-increment.md` §11。
5. **成绩可见范围**（假设：考生只能看自己的成绩与个人历史；科室成绩对比等统计仅管理员可见，出题人不可见成绩）。是否符合企业考核文化？

## 4. 验收要点（衡量标准）

- 录题 → 组卷 → 发布考试全流程可在 30 分钟内完成（含 50 题试卷）。
- 交卷后 3 秒内返回判分结果；判分准确率 100%（客观题）。
- 考生 A（科室 X）无法看到任何科室 Y 的考试、试卷与成绩数据。
- 时长耗尽自动交卷，切屏行为 100% 被记录且可被管理员查到。
- 桌面端 Chrome/Edge 最新两个大版本下功能与布局正常。
