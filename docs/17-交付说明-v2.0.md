## 2. ① 公告富文本与图片（含重要公告强提醒）

**背景**：v1.9 的公告正文为纯文本（`white-space: pre-wrap`），无法排版、无法插图，运营表达受限。

**实现**：**安全边界放在服务端**，前端 `v-html` 只负责渲染已净化内容。

| 环节 | 改动 |
| --- | --- |
| 长度上限 | `server/src/modules/content/content.schema.ts`：公告 `content` 5000 → **20000** 字符 |
| 服务端净化 | `content.service.ts` 新增 `sanitizeAnnouncementContent`，复用 `utils/richText.sanitizeRichText` 白名单：危险标签**连内容删除**、`on*` 事件属性剔除、图片仅接受内联 `data:image` 与站内附件签名 URL（`/api/attachments/<id>?t=<sig>`） |
| 空内容 | 净化后为空 → `1001`（前端 `richTextEmpty` 同口径预校验） |
| 统一入口 | 新建 / 编辑公告均走同一净化函数；列表、详情与双端 feed 下发的均为净化后正文 |
| 管理端控件 | `ContentViewPage.vue` 正文由 `textarea` 换成 `RichTextEditor`（加粗 / 列表 / 插入图片 / 粘贴截图，图片经对象存储回填站内签名 URL） |
| 双端渲染 | `ContentBoard.vue`（考试端）与 `PracticeNoticeCard.vue`（练题端）详情以 `v-html` + 全局 `.rich-text` 样式渲染 |

**重要公告首次进入强提醒**：级别为「重要」的公告在考生首次进入时强制弹出，以本地标记（考试端 `content-important-seen` / 练题端 `practice-important-seen`）保证**同一公告只提醒一次**；多条重要公告按序弹出。

**测试**：`server/src/test/v20a.test.ts`（本期 9 例，后续被 ③④ 扩展至 21 例）：危险标签 / 事件属性 / 非法图片过滤、合法图片保留、空内容与超长 `1001`、列表与详情一致性、编辑净化、双端 feed 净化。

## 3. ② 考试端首页数据后端化

**背景**：v1.9⑦ 的考生首页由前端「三次并发拉取（考试列表 / 成绩 / 未读数）+ 本地即时计算」拼装，存在两个问题：口径受前端分页上限限制（超 100 条记录后平均分失真）、首屏多次往返。

**实现**：新增 `modules/home`（`home.repo.ts` / `home.service.ts` / `homeProfile.service.ts` / `home.router.ts`）。

| 能力 | 口径 |
| --- | --- |
| 统计 | 待考（**进行中且无记录、排除免考**）/ 进行中 / 已交卷 / 平均分，并新增**及格率** |
| 及格线 | 优先取考试自身 `pass_score`，缺省回退系统设置 `examDefaultPassScore` |
| 趋势 | 最近 **10** 条已交卷成绩（考试名 + 分数 + 及格线 + 是否及格），按交卷时间倒序 |
| 待办 | 待考 / 未交卷 / 可申请补考 / 未读消息，按条件生成并附跳转路由 |
| 个性化 | 快捷入口与推荐题库由后端下发（v2.0⑥ 起按科室可配置） |

- **全量口径**：`home.repo` 直接查 `exam_records ∪ exam_records_archive`（`RECORD_SOURCE`）派生源，不受前端分页限制。
- **注册**：`app.ts` 挂载 `/api/home`，属考试域 —— **`PRACTICE_ONLY` 公网练题实例不注册本 router**。
- **降级**：前端 `ExamHomePage.vue` 改用聚合接口，新增待办提醒区、及格率卡片与最近成绩趋势条；接口失败静默降级，不阻断页面。

**测试**：`server/src/test/v20c.test.ts`（6 例）：权限、统计口径、趋势倒序与及格判定、待办生成、默认个性化入口、免考排除。

## 4. ③ 公告已读 / 轮播点击触达统计（双端）

**数据模型**：新增 `announcement_reads` / `banner_clicks` 两张**回执表**，唯一键按「内容 + 用户 + 端」去重（`uk_ann_read` / `uk_banner_click`），写入走 `INSERT IGNORE` —— **天然幂等**，重复上报不产生脏数据。

**后端**：

- `content.repo`：回执写入 + 批量人数统计（`COUNT DISTINCT`，按端拆分）+ 受众规模统计（考试端取在职考生数、练题端取在职账号数）。
- `content.service`：`markAnnouncementRead` / `markBannerClick`（目标不存在 → `1004`）；管理端列表回传每条内容的 `readCount` / `clickCount`；`getTouchStats()` 触达看板（受众规模 + 最近 **100** 条内容的阅读数/率、点击数/率）。
- **顺带修复既有缺陷**：轮播列表按关键字搜索会引用 `banners` 表并不存在的 `b.content` 列而报错 —— `buildFilter` 新增 `opts.withContent`，仅公告参与正文匹配（v1.9⑥ 遗留问题）。

**前端**：双端展示组件在**打开公告详情 / 强提醒弹出 / 点击轮播**时上报回执（失败静默，不干扰阅读）；管理端「公告与轮播」新增阅读 / 点击列与「触达概览」弹层。

**部署**：`deploy/db-grants-practice.sql` 追加两表 `SELECT, INSERT` 授权 —— 练题实例需写入回执，业务表（`announcements` / `banners`）仍**只读**。

**测试**：`v20a.test.ts` 扩展至 15 例：未登录 `401`、已读幂等、双端分端去重、点击幂等、目标不存在 `404`、看板权限与内容。

## 5. ④ 内容预约发布与批量上下线

**预约发布零新调度**：复用既有的生效时间窗 —— `start_at` 未到即「未生效」，到点由展示侧自动放出；`end_at` 到点自动下线。**不引入调度器**。

**批量操作**：

| 改动 | 说明 |
| --- | --- |
| 入参 schema | `contentBatchSchema`：`ids` 1~200 个 + `action ∈ {enable, disable, delete}` |
| 数据层 | 批量启停 / 批量删除（公告与轮播各一组，`WHERE id IN (…)` 占位符参数化，返回 `affectedRows`） |
| 服务层 | `batchAnnouncements` / `batchBanners`，返回受影响行数并落审计（`content.update` / `content.delete`，`targetId=batch`，`detail` 记录 action / requested / affected） |
| 路由 | `POST /api/content/announcements/batch`、`POST /api/content/banners/batch`（admin） |
| 管理端 | 两表新增多选列与「批量上线 / 批量下线 / 批量删除」按钮（带二次确认）；生效时间表单项补充预约与自动下线提示 |

**测试**：`v20a.test.ts` 扩展至 21 例：批量权限 `403`、入参校验、下线后两端不可见 + 重新上线、批量删除受影响行数、轮播批量下线、预约发布（未来开始时间 → feed 不可见）。

## 6. ⑤ 练题端打卡与激励（连续打卡 + 成就徽章）

**零迁移**：全部由既有 `practice_answers` / `practice_daily_tasks` / `practice_wrong_book` 派生，**不新增表**。

| 指标 | 口径 |
| --- | --- |
| `streakDays` 当前连续 | 以「有作答记录的业务自然日」集合计算；**今日未练则从昨日回溯**（不因「今天还没练」归零） |
| `bestStreak` 历史最长 | 集合内最长连续段，**断链后仍保留峰值** |
| 业务日切分 | 复用 `practiceDayOffsetMinutes(dailyResetHour)`，`resetHour = 0` 时零回归 |

**9 枚成就徽章**：初次练题 / 坚持三天 / 一周不辍 / 月度恒心 / 百题斩 / 五百题达人 / 精准射手（≥50 题且正确率 ≥90%）/ 每日一练达人（完成 10 次）/ 错题清零（≥20 题且错题本为空）。每枚含 `target` / `current` / `unlocked`，练题端首页按进度渲染（未解锁置灰，hover 显示达成条件）。

**配置化**：新增 `achievementEnabled`（默认 `true`）—— 关闭后练题端隐藏打卡与徽章入口，接口返回 `1017/404`，与 v1.9⑤ 的「学习报告 / 错题本 / 收藏夹」同一约定。配置项**三处同步**：后端 `practiceSettings.defaults.ts` ↔ 考试端 `constants/practiceSettings.ts` ↔ 练题端 `constants/practiceSettings.ts`。

**测试**：`server/src/test/v20b.test.ts`（15 例）：默认开启与字段下发、空数据不得假解锁、连续 3 天 = 3 且「坚持三天」解锁、今日未练从昨日回溯、断档后当前为 1 而历史最长保留 3、徽章阈值精确（49 题不解锁 / 50 题 88% 仍不解锁 / 50 题 100% 解锁）、120 题跨天解锁百题斩且五百题达人未解锁、每日一练 9 次不解锁 10 次解锁、模块关闭 `1017` 且恢复后数据不变、权威性交叉校验。

## 7. ⑥ 考试端首页个性化（科室级可配置）

**数据模型**：新增 `home_dept_configs` 表（第 37 张表）。`department_id` 为主键，**哨兵值 `*` 表示「全局默认」**；**不加外键**（`*` 不是真实科室，且科室删除后配置保留以便恢复同名科室）。

**生效优先级（服务端权威口径）**：

```
本科室配置行  →  全局默认行（department_id = '*'）  →  内置默认（全部启用、无推荐题库）
```

**按行覆盖、不做逐项合并**：科室一旦存在配置行，该行即为最终生效值（管理端保存时提交完整目录，行为可预期）；行内未提及的目录 key 视为**启用**，保证后续目录扩容时新入口不会静默消失。

| 能力 | 说明 |
| --- | --- |
| 快捷入口 | 固定目录（我的考试 / 我的成绩 / 我的补考 / 消息中心），可配置**启停 + 文案覆盖**（≤12 字；留空回落目录默认文案）。跳转与图标由系统目录决定，不可篡改 |
| 推荐练题题库 | 最多 **6** 个；**保存时**校验题库存在且 `allow_practice = 1`，**解析时二次过滤** —— 配置后被关闭对外练题则自动摘除，**不留死链** |
| 管理端页面 | 新增菜单「首页配置」（`/admin/home-config`）：配置范围选择（全局默认 / 各科室，含「已配置 / 继承全局 / 使用内置默认」状态标签）、快捷入口启停与文案覆盖、推荐题库多选、**生效预览**、已配置清单表格（编辑 / 重置）、脏检查与「放弃修改」 |
| 校验 | 科室须存在、至少保留一个快捷入口、题库须存在且已开放对外练题、题库数量上限（zod 层） |

**菜单 key 三端同步**：后端 `menuCatalog.ts`（key `home-config`，归入「考试运营」组）↔ `init.ts NEW_MENU_KEYS`（老库幂等合并授权）↔ 前端 `layouts/menuConfig.ts` + 路由 `meta.menuKey`。

**测试**：

- `server/src/test/v20d.test.ts`（20 例）：未配置零回归、全局行对所有科室生效（含未分配科室）、科室行覆盖且不影响其它科室、文案覆盖与空白回落、推荐题库下发（含题量与理由）、**死链过滤**（关闭对外练题后自动摘除、恢复后无需重配再生效）、保存校验（题库不存在 / 未开放 / 超上限 / 未知入口 / 全部关闭 / 文案超长 / 科室不存在）、author 与 examinee `1003`、总览接口字段、覆盖保存不产生重复行、`DELETE` 幂等与层级回落、目录扩容兼容。
- `src/views/admin/homeConfig.coverage.test.ts`（6 例）：目录驱动渲染（**禁止硬编码入口 key**）、哨兵 id、文案上限 12、题库上限 6、只列已开放题库、保存前「至少一个入口」校验。

## 13. 已知限制与注意事项

1. **富文本图片只认两种来源**：内联 `data:image`（粘贴小图）与站内附件签名 URL（`/api/attachments/<id>?t=<sig>`）。外链图片会被净化剔除 —— 这是**有意的 XSS / 防盗链收敛**，不做放宽。
2. **净化后的正文不再截断**：公告列表与 feed 下发**全文**（上限 20000 字符），页面渲染压力由 `.rich-text` 样式与浏览器承担；如后续出现超长公告，建议由运营侧控制篇幅而非恢复截断。
3. **触达统计不是「精确已读」**：回执在**详情被打开 / 强提醒弹出 / 轮播被点击**时上报，属「有效触达」而非「已阅完」。触达率的分母为对应端**在职账号数**，离职 / 停用账号不计入。
4. **触达看板最多展示最近 100 条内容**：与 v1.9 内容下发上限同源，超出部分需下架旧内容或按时间检索。
5. **首页配置为「按行覆盖」而非「逐项合并」**：科室存在配置行即整体生效，未提及的目录 key 视为启用。管理端保存时会提交完整目录，因此常规操作下行为可预期；**直接改库需自行保证行内含完整目录**。
6. **推荐题库不校验「题量 > 0」**：只校验 `allow_practice = 1`。空题库虽可被推荐，但练题端会因无题而无法开练 —— 建议运营侧只在题量充足的题库上做推荐。
7. **打卡与成就为即时派生计算**：连续天数由最近 400 天的作答日集合算出（`listAnsweredBizDates`），不落缓存、不建物化表。当前规模下开销可忽略；若单用户作答记录达百万级，建议加缓存或改成日粒度汇总表。
8. **`enabled` 布尔过滤的解析坑（沿用 v1.9 提醒）**：新增查询参数切勿直接用 `z.coerce.boolean()`（`'false'` 会变 `true`），沿用 `content.schema.ts` 中内置的正确解析器。
9. **练题端授权脚本必须与表变更同步维护**：任何新增的、练题端需要读写的表，都要在 `deploy/db-grants-practice.sql` 中登记（授权或明确零授权），否则公网实例会静默降级。

## 14. 后续建议（v2.1 候选）

按「用户价值 / 实施成本」排序，供下一轮迭代取舍：

1. **考试端首页个性化第二层：角色维度**。当前已支持科室级；可叠加按角色（如新员工 / 主管）下发差异化入口，优先级「角色 > 科室 > 全局」。
2. **触达看板导出与趋势**。当前只有当前快照；可加「按日阅读量趋势」与 Excel 导出（复用 v1.7② 导出列白名单机制）。
3. **公告定向范围细分**。当前 `target` 仅「考试端 / 练题端 / 两端」；可细化为「指定科室 / 指定人群」，与 v2.0⑥ 的科室配置共用一套选择器。
4. **打卡激励的运营化**。当前徽章为内置固定 9 枚；可把徽章条件做成可配置项，并支持「连续打卡 N 天」的积分 / 提醒推送（复用 v1.7④ 通知模板）。
5. **练题端学习路径**。基于错题本与科目正确率自动生成「薄弱知识点 → 推荐题库」路径，与首页推荐题库打通。
6. **首页配置的灰度与预览**。支持「以某考生身份预览首页」与配置变更历史（复用审计日志），降低误配成本。
