## 2. ① 考试运营闭环

### 2.1 O1 试卷 PDF 导出

- `GET /api/papers/:id/export-pdf?withAnswer=1`（admin/author，author 需被授权该试卷来源题库）—— 考生版 / 答案版。
- 排版：`utils/pdfExport.ts` 新增 `buildPaperPdfBuffer`（题目列表式，非表格）——标题 + 摘要（总分/题量/来源题库）+ 逐题（题干、选项，答案版附参考答案与解析），自动换行与分页。
- 答案文本化：客观题转选项文本（判断题显示「正确/错误」）；填空按空 ` / ` 拼接；简答取参考文本。
- 前端「试卷管理」操作列新增「导出 PDF」下拉（考生版 / 答案版）。

### 2.2 O2 成绩复核申请流

- 新表 `score_appeals`（按 `record_id` 唯一，每条答卷至多一次；外键 CASCADE 到 `exam_records`）。
- 规则：仅本人 `submitted` 记录可申请；考试级三态开关 `exams.allow_appeal`（null 继承全局 `appealEnabled`）；申请时限 `appealWindowDays`（天，0 = 不限）；被驳回不可再次申请。
- 复核：`POST /api/appeals/:id/approve`（改分 0~试卷总分，**直接更新记录总分 + 审计留痕 + 通知考生**）/ `POST /api/appeals/:id/reject`（意见必填）。
- 接口：`POST /api/appeals/apply`、`GET /api/appeals/my`（考生）、`GET /api/appeals`（admin，可按状态过滤）。
- 前端：新增「成绩复核」菜单 + `admin/AppealManagePage.vue`；考生「我的成绩」页新增「申请复核」入口。
- 审计动作：`appeal.approve` / `appeal.reject`（目标类型 `appeal`）。

### 2.3 O3 特殊考试安排

- 新表 `exam_exceptions`（按 考试×考生 唯一）：`extra_minutes` / `extra_attempts` / `exempt` / `note`。

- 前端：考试管理新增「特殊安排」入口 + `admin/ExamExceptionDialog.vue`。

## 3. ② 题库与数据运营深化

### 3.1 Q1 知识点（标签）体系

- 存储：`questions.tags JSON NULL`（DDL + `db/init.ts` 幂等迁移）；`QuestionDto.tags: string[]`（空数组 = 未打标签）。
- 归一化：`questions.service.normalizeTags()` —— trim → 去空 → 去重（保序）→ 单标签截断 32 字 → 最多 `MAX_TAGS = 10` 个；zod 层同步 `.max(10)` 中文提示。
- 过滤：`questions.repo.buildWhere` 支持 `tag` → `JSON_CONTAINS(tags, JSON_QUOTE(?))`。**题库内列表**（`GET /api/banks/:id/questions?tag=`）与**全局试题池**（`GET /api/questions?tag=`）均支持；题库内列表题型过滤同时放开为全部 5 种题型。
- 标签选项：新增 `GET /api/questions/tags?bankIds=`（跨题库展开 JSON 数组、去重、按中文排序；author 限定被授权题库）。
- **组卷按知识点配比**：`POST /api/papers/draw-questions` 新增 `tagRules: Array<{tag, count, score}>`，与题型 `rules` 可同时使用。
  - 两阶段执行：先对全部规则做**存量预检**，任一不足即整体作废并返回 `tagShortages`（HTTP 200，不生成任何题目）；预检通过后逐规则抽取，规则间通过 `id NOT IN (...)` 排除已抽中题目**自动去重**。
  - 返回结构 `DrawResult` 增 `tagShortages: DrawTagShortage[]`。
- **看板知识点归因**：`DashboardReportDto.tagWrong`（一题多标签则每个标签各计一次；未打标签题目不计入；简答不纳入）。
- 前端：`QuestionFormDialog` 增「知识点标签」多选（支持回车创建，候选来自同题库已有标签）；`QuestionBankDetailPage` 增标签列 + 「全部知识点」筛选；`PaperComposerPage` 抽题模式增「按知识点配比」规则行（可增删、去重校验）与题池标签筛选。

## 4. ③ 安全与合规加固

> 拆两批交付：**③-a = T1 + T2**（commit `d9c3f4f`）；**③-b = S1 + S2**（commit `997e93a`）。

### 4.1 T1 图形验证码（替换自研算术题）

- 新增 `utils/captcha.ts`（零依赖）：`crypto.randomInt` 生成 4 位（字符集去 `0/O/1/I/L/Z` 易混字符），逐字旋转 + 干扰线 + 噪点 → **SVG Base64 Data URI**。
- 答案服务端内存缓存（TTL 5min）、**一次性消费**、大小写不敏感；`GET /auth/captcha` → `{ captchaId, image }`。
- 阈值由设置项 `loginCaptchaAfterFails`（默认 3）驱动；新增错误码 **1015 `CAPTCHA_REQUIRED`（400）**；练题端复用同一实现。

### 4.2 T2 账号安全加固

- **登录审计**：新表 `login_logs`（自包含、无外键、fail-open 写入；成功与失败均落库；`source` 区分 admin/practice；3 索引）；查询 `GET /login-logs`（admin，按 username/success/source/时间范围）。
- **密码策略（可配）**：新增 `utils/passwordPolicy.ts`（`assertPasswordPolicy` 抛 1001 中文聚合文案 / `isPasswordExpired`）；设置项 `passwordRequireUpper/Lower/Digit/Symbol`（默认 false）+ `passwordExpireDays`（默认 0 = 不过期）；`users` 增 `password_changed_at DATETIME(3)`（迁移回填 = `created_at`）；登录超期返回 `LoginResult.passwordExpired`。
- **会话/设备**：JWT 增 `jti`（= 会话 id）；新表 `user_sessions`（`revoked_at`/`expires_at`/`last_seen_at` + 2 索引）；`authRequired` 改 async，带 `jti` 时校验会话（撤销/过期 → 1002），不带 `jti` 的旧令牌兼容放行；`touchSession` 5min 内不重复写库；`GET/DELETE /auth/sessions(:id)` + logout；管理员 `GET/DELETE /users/:id/sessions` 强制下线；重置密码后自动 `revokeAll` 该用户全部会话。
- **两步验证（零依赖 TOTP，RFC 6238）**：`utils/totp.ts`（Base32 编解码 + HMAC-SHA1 + 30s/6 位 + ±1 步窗口）；`users` 增 `two_factor_secret` / `two_factor_enabled`；设置项 `twoFactorAvailable`（默认 true）；登录启用后返回 5min 挑战令牌（`scope=2fa`，`authRequired` 拒绝用作访问令牌），`POST /auth/2fa/verify` 换正式令牌；`/auth/2fa/policy|setup|enable|disable`。
- 前端：`CaptchaImage.vue`（v-model captchaId + refresh）；`AccountSecurityDialog.vue`（密码策略/两步验证/登录设备三卡片 + UA 归一「系统 · 浏览器」）；`LoginPage` 双阶段（credentials/twofa，含返回重输账号）+ 1015 自动显验证码；`AppLayout` 顶栏「账号安全」；`LoginLogPage.vue` + 菜单/路由；`SettingsPage` 账号安全 Tab 增验证码阈值/密码复杂度 4 开关/密码有效期/2FA 开关；`UserPage` 增「强制下线」。

### 4.3 S1 简答富文本/图片作答 + 评分细则（rubric）

- **富文本**：新增 `utils/richText.ts`（**零依赖白名单重建**）——`sanitizeRichText` 先删注释与危险标签整段（script/style/iframe/svg/form… ），再逐标签重建（标签白名单 + 属性白名单 `a[href,title]` / `img[src,alt,width,height]`，`on*` 事件属性天然剔除）；`a[href]` 仅允许 http/https/mailto/tel 与站内相对地址（杜绝 `javascript:`）；`img[src]` 仅允许 `data:image/(png|jpe?g|gif|webp|bmp);base64,`，并限制**单图体积**（默认 512KB + 64B 容差）与**图片张数**（默认 3）；输出长度上限 20000 字符。`isRichTextEmpty` 判空。
  - **安全边界在服务端**：`records.service.saveAnswers` 对 `short` 题作答调用 `sanitizeRichText`；前端 `v-html` 渲染仅作展示。`express.json` 上限 2mb → **8mb**（支持内联图片）。
  - 前端新增 `src/components/common/RichTextEditor.vue`（`contenteditable` + 原生 `execCommand`，工具栏加粗/斜体/下划线/列表/插入图片/清除格式；选图 `FileReader` → data URI 内联）；`QuestionCard.vue` 简答作答接入；`ReviewPage.vue` / `ScoreDetailPage.vue` 以 `v-html` 渲染（新增全局 `.rich-text` 样式）。
- **rubric**：`questions.rubric JSON NULL`（DDL + `db/init.ts` 幂等迁移）；`QuestionDto.rubric: RubricBand[]`（`{ score, label, description }`）。归一化 `normalizeRubric`：**仅简答保留**、分值去重降序、最多 10 档、`label ≤32` / `description ≤200`；zod `.max(10)`；批量编辑透传。前端 `QuestionFormDialog.vue` 简答增「评分细则」编辑区；`ReviewPage.vue` 按 rubric 渲染**分档快选按钮**（点击即填入该档分值，默认预选最高档），总分 = 客观分 + 主观分。

### 4.4 S2 题库授权批量维护

- 新增接口（**仅 admin**）：`POST /api/banks/:id/authors/grant` / `POST /api/banks/:id/authors/revoke`。

- 前端：新增 `src/views/author/BankAuthorBatchDialog.vue`（科室树 + 含子科室开关 + 角色过滤 + 手选出题人；客户端即时预演命中人数/将授权人数/已授权跳过数）；`QuestionBankDetailPage.vue` 新增管理员可见「批量授权」入口。

## 5. ④ 工程化与稳定性

> T4（Docker / CI / Playwright）按决策**剔除**；不新增破坏性变更，归档采用「搬移 + 读路径 union」。

### 5.1 T3 实时考试监控（轮询大屏，admin）

- **花名册口径**：考试所辖科室（含子树）内的 `examinee` 账号 ∪ 「已有答卷但已不在花名册」（如考生调岗后仍有记录），保证不漏人。
- **行状态** `MonitorStatus`：`not_started` / `in_progress` / `pending_review` / `submitted`；取每人**最新一次作答**（`MAX(attempt_no)`）。
- **剩余秒数**（仅进行中有意义）：服务端按 `min(开考 + (时长 + 加时) × 60s, 考试结束时间)` 计算；前端本地每秒递减、每轮轮询后按服务端值重置，避免时钟漂移。
- **监考加时**：复用 `exam_exceptions.extra_minutes`（**累加**，单次 1~600 分钟），与 v1.7① 特殊安排同一数据源。
- **强制交卷**：复用 `records.service.submit(recordId, userId, auto=true)`，保持判分/幂等语义一致；写审计 `record.force_submit`。
- **接口**（均 `requireRole('admin')`）：`GET /api/exams/:id/monitor`、`POST /api/exams/:id/monitor/:userId/force-submit`、`POST /api/exams/:id/monitor/:userId/extend`（`{ minutes }` 1~600）。
- 前端：`src/views/admin/ExamMonitorPage.vue`（7 张汇总卡 + 明细表 + 自动刷新开关 / 15s 轮询 + 剩余时长/切屏高亮 + 加时/强制交卷操作）；`ExamManagePage.vue` 操作列新增「监控」入口。

### 5.2 S4 题库复制

- `POST /api/banks/:id/clone`（admin/author）：`{ name?, copyQuestions?=true, authorIds? }`。
  - 名称缺省为「原名（副本）」，`≤100` 字。
  - 复制试题时**新 id 全量复制**（题型/选项/答案/分值/解析/科目/标签/rubric），事务内完成。
  - 授权出题人：admin 可显式指定 `authorIds`（校验合法性）；否则继承源库作者（author 复制时自动含自己）。
- 审计 `bank.clone`（detail 记录源库、copyQuestions、copied 数、authorIds）。
- 前端：`src/views/author/BankCloneDialog.vue` + `QuestionBankListPage.vue` 卡片操作区「复制」入口（admin 可见作者选择）。

### 5.3 T5 数据归档与性能

- **新增表 `exam_records_archive`**（表 30；14 业务列 + `archived_at`；**无外键**，可长期独立保留）；3 索引 `idx_archive_exam` / `idx_archive_user` / `idx_archive_archived_at`。
- **归档语义 = 搬移**：`INSERT ... SELECT` 入归档表 → `DELETE` 业务表，两表无重复行。
- **安全边界**：仅 `status='submitted'`（已出成绩）+ `exams.end_time < cutoff` + **无 `score_appeals` 申请**（有复核申请的必须留在业务表，因外键约束）；`pending_review` 不参与归档。返回 `ArchiveResultDto { archived, skipped, cutoff, archiveTotal }`。

- **性能索引**（幂等迁移）：`exam_records.idx_records_exam_status (exam_id, status)`、`exam_records.idx_records_status_submitted (status, submitted_at)`、`login_logs.idx_login_logs_source_created (source, created_at)`。

- 设置：新增 `archiveRetentionDays`（0 = 未启用自动归档，0~3650）。

## 11. 已知限制与注意事项

- **归档不可逆**：`exam_records_archive` 为「搬移」目的地，归档后业务表不再保留该行；如需回溯请直接在归档表查询（读路径已 union，接口层无感知）。
- **有复核申请的记录不归档**：为保证 `score_appeals.record_id` 外键完整性，存在成绩复核申请的记录**必须留在业务表**，归档会跳过并计数。
- **实时监控为轮询**：非 WebSocket 推送，默认 15s 一轮，存在最长一轮的延迟；剩余时长由前端每秒递减、轮询后以服务端值为准（不会累积漂移）。
- **监考加时为累加**：多次加时叠加，单次 1~600 分钟；与 v1.7① 特殊安排共用 `exam_exceptions.extra_minutes`，两处修改互相可见。
- **富文本安全在服务端**：前端 `v-html` 仅作展示；所有富文本作答入库前经服务端白名单净化，`express.json` 上限 8mb。
- **两步验证密钥存储**：`two_factor_secret` 明文存库（自建内网系统，未引入 KMS）；如需更高等级可后续接入加密存储。
- **PDF 中文字体依赖**：非 Windows 环境（Linux/容器/CI）默认可能无 `simhei` 等字体，务必设置 `PDF_FONT_PATH`，否则中文可能显示为方框。
- **红线**：所有脚本/测试仅针对 `enterprise_exam_system`（及测试库 `..._test`）；**严禁**操作同实例下的其他库（如 `exam_system`）。
