# 全站设计合规审计报告 · v2.2

> 审计对象：管理端（`src/`）+ 公网练题端（`practice-web/src/`）
> 依据：《管理端设计规范 v2.1》§1–§12（含本轮新增 §2.5）
> 方法：**以规范反查实现** —— 不再新增功能，而是把已发布的规矩拿去全库对照，找「写了但没做到」和「规范自己打自己」

## 一、结论

v2.1 的 5 项迁移清单虽然全部标记完成，但**规范自身与实现之间仍有 10 类不一致**，其中 1 类是可访问性硬伤（练题端 12 处文字对比度低于 WCAG AA）。本轮全部修复，并把每一条结论落成 **CI 可执行断言**，防止回潮。

| 端 | typecheck | 测试 | 构建 |
|---|---|---|---|
| 管理端 | ✅ | ✅ **160/160**（15 文件） | ✅ |
| 练题端 | ✅ | ✅ **24/24**（4 文件，样式护栏 4 → 8 条） | ✅ |

## 二、发现分级

### P0 · 可访问性硬伤（必须修）

**练题端 12 处「语义原色直接作文字色」**，其中 `$color-warning`（`#F59E0B`）对白底仅 **2.15:1**，远低于 WCAG AA 正文下限 4.5:1。

| 位置 | 原写法 | 实测对比度 | 修复 |
|---|---|---|---|
| `QuestionCard` 题型徽标「判断」 | `color: $color-warning` | **2.15:1** ❌ | `$color-warning-text`（5.02:1） |
| `PracticeOptionModal` 空选项提示 | `color: $color-warning` | **2.15:1** ❌ | `$color-warning-text` |
| `PracticeFeedback` 正确答案 | `color: $color-success` | 3.30:1 ❌ | `$color-success-text`（5.02:1） |
| 其余 9 处（得分数字 / 错题标记 / 删除按钮等） | `color: $color-success｜error` | 3.30–4.83:1 ⚠️ | 对应 `-text` 档 |

根因：**练题端的语义色三件套（`-bg` / `-border` / `-text`）此前完全没定义**——只有原色，开发者拿不到合规的文字档，只能将就用原色。本轮补齐三件套（与管理端同源同值）。

### P1 · 规范冲突（应当修）

1. **蓝紫渐变残留**：`$gradient-brand` = `#2563eb → #4f46e5 → #7c3aed`，中间两站是 indigo-600 / violet-600——与「冷静蓝 · 单一主色」的定位直接冲突。管理端 8 处 + 练题端 1 处引用。
2. **实色化没走完**：规范 §7 写明「logo 实色 blue-600，**无光晕无渐变**」，但顶栏用户头像仍用品牌渐变。
3. **规范外色值**：`$color-primary-50` / `THEME.primary50` = `#EEF2FF`（indigo-50）——**不在规范的 10 档之内**，且与语义重叠的 `$color-primary-soft`（`#EFF6FF`）双名并存、值还不同。

### P2 · token 卫生（值得修）

4. **token 逃逸**：`StatusTag` 中性标签硬编码 `#E2E8F0` / `#F1F5F9`（即 n-200 / n-100），绕过 token 后统一改色会漏掉它。
5. **硬编码主色**：管理端 9 处 + 练题端 3 处 `rgba(37, 99, 235, …)`，把主色写死成了字面量。
6. **分类色语义失序**：`$color-secondary`（紫）到底是什么色？没有任何注释；底色靠 `rgba($color-secondary, 0.08)` 手调透明度。
7. **注释与实现不符**：题型色注释写「填空**青**」，实现用的是 `success`（**绿**）。
8. **规范文档自相矛盾**：§1 仍写「默认密度行高 48 / 紧凑 40」，而 §8.3 上一轮已按实测校正为「40 / 32」——同文档两个数字打架。
9. **内部标记符残留**：§2.2 的 n-400 行留着「装饰 ⚠️ 见 2.4」这种编辑期便签。
10. **练题端死 token**：`$sidebar-*` 全套（7 个）与 `$gradient-brand` 引用数为 **0**，是从管理端复制模板带过来的。

## 三、修复对照

### 色彩：去紫

| 项 | 修前 | 修后 | 说明 |
|---|---|---|---|
| `$gradient-brand` | `#2563eb → #4f46e5 → #7c3aed` | `#2563eb → #1d4ed8 → #1e40af` | 同色系蓝（blue-600/700/800），保留层次、去掉紫色相 |
| 顶栏头像 | 品牌渐变 | `$color-primary` 实色 | 对齐规范 §7 |
| `$color-primary-50` | `#EEF2FF`（indigo-50） | `#EFF6FF`（blue-50） | 回到规范 10 档内 |

### Token 收口

| 项 | 修前 | 修后 |
|---|---|---|
| 中性标签底 / 描边 | `'#E2E8F0'` / `'#F1F5F9'` | `THEME.border` / `THEME.neutralBg`（新增） |
| 主色透明阴影（12 处） | `rgba(37, 99, 235, X)` | `rgba($color-primary, X)` |
| 题型徽标底 | `rgba($color-secondary, 0.08)` | `$color-secondary-soft` = `#F5F3FF`（新增） |
| 错误类浅底（练题端 4 处） | `#fef2f2` / `#fecaca` | `$color-error-bg` / `$color-error-border` |

### 新增规范条款 §2.5 · 分类色（题型编码）

明确「单一主色」的**唯一例外**：题型编码属分类信息，需要多色相帮考生识别，可走分类色板；且分类色**只做分类表达、不表达状态**，不得外溢到列表页 / 表单页 / 侧栏。

| 题型 | 色相 | 文字档 | 浅底 |
|---|---|---|---|
| 单选 | 蓝 | `$color-primary` | `$color-primary-soft` |
| 多选 | 紫 | `$color-secondary` | `$color-secondary-soft` |
| 判断 | 橙 | `$color-warning-text` | `$color-warning-bg` |
| 填空 | 绿 | `$color-success-text` | `$color-success-bg` |
| 简答 | 灰 | `$text-secondary` | `$color-table-head` |

## 四、护栏：把结论变成断言

审计的价值不在「这次改对了」，而在「下次改错会红」。

| 测试文件 | 新增断言 |
|---|---|
| `theme.test.ts` | 同源对 18 → **21 组**：补 `primary50` / `secondary` / `secondarySoft` / `border` / `neutralBg`，SCSS ↔ TS 漏改即失败 |
| `globalStyle.test.ts` | +3：品牌渐变**不得含** `#4f46e5`/`#7c3aed`（且必须从 blue-600 起）；`#EEF2FF` 不得出现在任何样式文件；视图层不得硬编码 `rgba(37, 99, 235, …)` |
| `practice-web/styleGuard.test.ts` | **新增 4 条**：`color: $color-<语义原色>` 一律禁止（负向后顾排除 `border-color` 等）；三件套定义齐全；错误浅底不硬编码；`#EEF2FF` 不出现 |

其中「语义原色作文字」这条护栏在首次运行时即抓到 `variables.scss` 里的 `#FEF2F2`——属 token 定义本身，遂把硬编码检查收敛到 `views/`、`components/`、`layouts/` 业务层，避免误报。

## 五、遗留待决策 → 已落地（v2.2.1）

本轮审计时按「不擅自改公网实例的功能色」原则搁置的两项，经确认后已执行完毕，**仅动练题端**。

### 1. 练题端双主色并存 ✅ 已收口

问题比「引用分散」更深一层：**Element Plus 主题基色写的是管理端主色 `#2563eb`**，而练题端自定义组件用 `$practice-primary`（`#1d4ed8`）——EP 按钮 / 选中态与自定义按钮因此呈现两个蓝。

- `element/index.scss` `$colors.primary.base`：`#2563eb` → `#1d4ed8`
- `index.scss` `:root` 的 `--el-color-primary` 系列改由 `$practice-primary` 驱动，浅档编为 blue-500…100 阶梯
- `QuestionCard.vue` 16 处 + `index.scss` 6 处 `$color-primary*` → `$practice-*`；业务层 3 处硬编码主色（含图表 `fill="#1d4ed8"`）→ token / CSS 类
- 补齐 `$practice-primary-light: #3b82f6`；**删除** `$color-primary*` / `$color-secondary*` 系列（练题端不再有第二套主色）
- 真机实测：EP 主按钮计算值 `rgb(29, 78, 216)` = `#1d4ed8` ✅

### 2. 练题端多选题型用紫 ✅ 已改青

`$color-secondary` = `#7C3AED`（violet-600）正是「冷静蓝」明令禁止的紫。题型编码虽是 §2.5 的分类色例外，但练题端约定更严，故改为青色分类 token：

| 题型 | 修前 | 修后 |
|---|---|---|
| 单选 | 蓝 | 蓝（`$practice-primary`） |
| **多选** | **紫** `#7C3AED` | **青** `$type-multiple-text` `#0E7490`（5.2:1 ✅）+ `$type-multiple-soft` `#ECFEFF` |
| 判断 | 橙 | 橙（不变） |

> 说明：管理端 `$color-secondary`（紫）**未改**——它还兼作仪表盘统计卡强调色，且 §2.5 已明确分类色的合法多色相。若希望两端题型色统一，可作为后续事项单独评估。

### 3. 附带：死 token 清理（12 个）

`$sidebar-*`（7，练题端无侧栏）、`$gradient-brand`、`$header-height`、`$shadow-card`、`$shadow-md`、`$radius-xl`、`$color-info-50`。

### 新增护栏（练题端 `styleGuard.test.ts`，4 → 8 条）

业务层禁硬编码主色 · 禁 `$color-primary` / `$color-secondary` 残留 · 分类色禁 violet · EP 主色须与 `$practice-primary` 同源。
