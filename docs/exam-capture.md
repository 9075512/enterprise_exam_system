# 考试抓拍部署与验收

## 功能入口

- 管理员 → 系统设置 → 作答与防作弊：设置抓拍默认开关、间隔、摄像头异常策略和照片保留天数。
- 管理员 → 创建/编辑考试 → 考试抓拍：分别覆盖开关、间隔和异常策略，或跟随全局；页面显示解析后的规则。
- 考生 → 我的考试 → 开始/继续：启用抓拍时先说明用途并授权、预览、拍照。新的答卷在首照保存成功后开始计时；继续考试保持原答卷和原计时。
- 管理员 → 实时监考 → 考试抓拍，或成绩报表 → 查看抓拍：查看按作答次数关联的照片、到期状态及摄像头事件，点击照片放大。

默认关闭；启用后默认每 5 分钟抓拍，摄像头必须开启，照片保留 30 天。必拍模式下摄像头中断会遮挡题目，答案保留、计时继续，可正常交卷或暂存退出。可选模式只提醒并记录。上传失败最多尝试三次，同一采集标识去重；上传问题不会阻止答题和交卷。

前台运行时进行周期抓拍；浏览器后台和 App 后台会暂停采集，回来后重新打开并补拍。摄像头状态来自客户端报告，服务端会另外标记长时间没有收到照片的“抓拍逾期”，此状态供人工复核，不自动判作弊。

## 数据库与服务升级

先备份数据库，安装服务端依赖并构建。针对已有库运行独立增量升级，无需重建或重新灌入种子数据：

```powershell
npm --prefix server ci
npm --prefix server run db:migrate:captures
npm --prefix server run build
npm run build
```

迁移可重复执行：为 `exams` 增加 `capture_settings`，新建 `exam_capture_sessions`、`exam_captures` 和 `exam_camera_events`。新安装的 `db:init` 也包含相同结构。历史答卷没有抓拍会话时视为关闭；启用全局规则不会追溯开启历史作答。

每次正式开考冻结完整规则及保留天数。照片到期时间按服务端接收时间计算，后续修改保留天数不追溯改变旧照片。会话和照片不依赖活动答卷表的外键，答卷归档后关联仍保留。

## 私有图片目录

配置服务端环境变量：

```dotenv
CAPTURE_STORAGE_DIR=/opt/enterprise-exam/shared/exam-captures
```

相对路径以 `server` 目录为基准，默认 `storage/exam-captures`。目录必须允许服务进程读写，且应位于发布目录之外以跨版本保留。勿将此目录映射为 Nginx 静态文件目录。备份时同时备份数据库和该目录。

浏览器采集压缩 JPEG，最长边不超过 640 像素。服务端限制单张 2MB，并解码验证实际图片及限制解码资源。预览通过管理员 Bearer 鉴权读取 Blob，响应禁止缓存；没有匿名访问或长期签名链接。

服务启动后和每小时自动分批清理到期图片。删除文件成功后才标记清理完成，失败留待下次重试。照片元数据、摄像头事件及“已过期”状态保留。服务停止期间不执行清理，恢复后补清。

## HTTPS 与安卓

生产环境请配置可信的 HTTPS 证书，使用 [HTTPS Nginx 示例](../deploy/nginx-exam-https.conf) 替换域名和证书路径。保留原有视频/APK 上传和 SSE 代理设置。浏览器访问普通内网 HTTP 地址无法使用摄像头；本机 localhost 可以用于开发验证。不要通过忽略证书校验或允许不安全来源来绕过。

安卓新版为 `1.0.5`，增加摄像头运行时权限；仅对配置服务器的 HTTPS 同源页面授权视频采集，不申请麦克风权限。拒绝授权、取消请求、页面跳转和销毁均有处理。更换服务器地址后需要重新登录。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File mobile/build-android.ps1 -ServerUrl https://exam.example.com
```

安卓 1.0.5 预置服务器地址为 `https://139.9.134.68`，使用受信任的 IP 证书。服务器保留 HTTP 以兼容旧版 App；抓拍需使用 HTTPS。发布构建沿用现有签名，版本号已递增；调试包使用调试签名，不能用于覆盖已签名的正式版。

## 接口

电脑答题页大于 1100px 时，摄像头固定在右栏考生信息下方，答题卡独立滚动；1100px 及以下显示在题目上方。布局切换复用同一个摄像头实例。

管理员可从实时监考或历史成绩的抓拍抽屉删除单张照片，或勾选当前页批量删除。删除需要确认，图片不可恢复；时间线保留“管理员已删除”、操作人姓名快照和时间。已删除和过期照片不可选择。删除不影响答案、成绩、异常事件、后续抓拍以及历史采集数量与最近上传时间。

删除标记提交后图片接口立即拒绝读取，随后清除私有文件。文件清理失败由启动及每小时任务重试；`removed_at/removed_by/removed_by_name` 保存管理员删除信息，原 `deleted_at` 仅表示文件清理完成。既有备份仍按部署备份策略保留，本接口不修改备份文件。

| 接口 | 权限与行为 |
|---|---|
| `GET /api/exams/:id/capture-config` | 本场参与考生；正在作答时返回已冻结配置 |
| `POST /api/exams/:id/start` | 兼容原 JSON；拍照使用 multipart 字段 `file`、`captureId`，无摄像头的可选模式提交 `reason` |
| `POST /api/records/:recordId/captures` | 本人进行中的答卷；multipart `file`、`captureId`、`kind=periodic/resume` |
| `POST /api/records/:recordId/captures/events` | 本人进行中的答卷；`eventId`、`status`、`reason`，重复事件不改变最新状态 |
| `GET /api/records/:recordId/captures` | 仅管理员；`page`、`pageSize`，返回照片、事件及各自总数；支持归档答卷 |
| `GET /api/records/:recordId/captures/:captureId/image` | 仅管理员；私有 JPEG，过期或不存在返回 404 |
| `DELETE /api/records/:recordId/captures/:captureId` | 仅管理员；删除单张照片，重复删除幂等 |
| `POST /api/records/:recordId/captures/batch-delete` | 仅管理员；`{ captureIds: string[] }`，1～50 个，去重后处理；不存在或跨答卷整批拒绝 |

删除接口返回 `{ deletedCount, alreadyDeletedCount }`；照片列表增加 `status=available/expired/deleted`、`deletedAt` 和 `deletedBy: { id, name } | null`，保留原字段。审计动作 `capture.delete` 记录答卷标识、照片标识和本次新删除数量。进行中、已交卷、已归档答卷均支持管理员删除。

事件状态：`ready`、`unavailable`、`interrupted`、`upload_failed`。监考摘要另有 `disabled`、`unknown`、`overdue`。照片列表时间为服务端接收时间。

## 验证

自动化测试覆盖配置继承、冻结、旧记录兼容、必拍失败不产生答卷、保存失败回滚文件和答卷、重复采集去重、权限、分页、摄像头中断和恢复、断网上传重试、正常及到时交卷、归档关联、到期清理和重复迁移。

正式启用抓拍前，仍需在实际 HTTPS 地址下用电脑摄像头及安卓真机完成以下检查：允许/拒绝授权、设备占用、摄像头拔出、后台恢复、断网恢复、手动交卷、到时交卷，以及管理员查看同一考生的多次作答。自动化中的摄像头使用模拟设备，不能替代真实硬件兼容性验收。

本版用于抓拍留存和人工复核，不包含自动人脸比对或活体检测。
