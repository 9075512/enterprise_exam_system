## 2. ① 练题端题库 / 每日一练不可见（缺陷修复）

**用户反馈**：练习端每日一练看不到、题库也看不到。

**根因（非玄学）**：`question_banks.allow_practice` 是练题端一切内容的**唯一入口闸门**，而种子数据把它留作默认 `0`，导致

- `GET /api/practice/banks` 恒返回空数组 → 练题端「题库」为空；
- 每日一练抽题同样以 `allow_practice = 1` 过滤 → 抽到 0 题，前端按 `total === 0` 隐藏卡片 → 「每日一练」不可见。

**修复**：

| 改动 | 说明 |
| --- | --- |
| 种子默认开放 | `server/src/db/seed.ts` 题库种子 `allow_practice = 1` |
| 批量开/关接口 | `POST /api/banks/practice/batch`（仅 admin，只改 `allow_practice`，写 `bank.practice_flag` 审计） |
| 空题拦截 | 每日一练无题可抽时抛 `1014`（原返回 200 + 0 题会话，前端会渲染出一个空练题流程） |
| 管理入口 | 「练题端设置」页新增「练题题库（对外开放）」卡片：行级开关 + 汇总 + 高危提示 |
| 空态文案 | 练题首页空态明确提示「请联系管理员在『练题端设置』中开放题库」 |

**测试**：`server/src/test/practice.banks.test.ts`（17 例）把「种子默认开放 → 两端可见」固化为回归护栏。

## 3. ② 管理端侧栏二级分组（含折叠态缺陷修复）

**用户反馈**：左侧菜单有点乱，帮我归一下类；菜单收回后显示异常。

**分组方案**（用户确认「5 组 + 可折叠二级菜单」）：数据中心 / 教学资源 / 考试运营 / 练题运营 / 组织与系统（另含考生中心），17 项平铺菜单全部归位；**组内只有一项时不套折叠**，避免「一个孩子的折叠组」。

**分组为纯展示层**：菜单 key 与后端 `MENU_CATALOG` 完全不变，因此 **菜单权限矩阵 / 路由 `meta.menuKey` / 后端 `requireRole` 三重同步不受影响**；「菜单权限」页也按分组归类展示（`span-method`）。

**折叠态异常根因**：`AppLayout.vue` 的兜底选择器写成 `:deep(.el-menu--collapse)`，而 `.el-menu--collapse` 与 `.layout__menu` 是**同一元素**，后代选择器永不命中 → Element Plus 折叠宽度 64px 大于侧栏 44px，图标被裁切。改为 `&.el-menu--collapse` 后命中。此外二级页进入时自动展开所在组并回退高亮。

**测试**：`src/layouts/menuConfig.test.ts`（13 例）。

## 7. ⑥ 公告与轮播图（双端发布）

**用户需求**：新增公告管理 + 轮播图，同步考试端与练习端（可选同时发布两端或单独发布某一端）。

### 7.1 数据模型（2 张新表）

| 表 | 关键列 |
| --- | --- |
| `announcements` | `target`(exam/practice/both) · `level`(normal/important) · `pinned` · `enabled` · `start_at`/`end_at` |
| `banners` | `image_url` · `link_url` · `sort_order` · `target` · `enabled` · `start_at`/`end_at` |

两表均带 `created_by` + `created_at`/`updated_at`；索引 `(target, enabled)` 支撑双端展示查询。

### 7.2 后端模块 `modules/content`

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/content/announcements` | admin | 公告分页列表（target / enabled / keyword 过滤） |
| `POST` `PUT /:id` `DELETE /:id` | admin | 公告增删改（整对象提交） |
| `GET /api/content/banners` + 增删改 | admin | 轮播图同上 |
| `GET /api/content/feed?scope=exam` | 登录 | **考试端**当前生效的公告 + 轮播图 |
| `GET /api/practice/feed` | 练题登录 | **练题端**当前生效的公告 + 轮播图 |

**关键设计：练题端复用同一实现**。练题实例（`PRACTICE_ONLY`）**不注册考试域路由**（`/api/content` 物理不可达），因此练题端展示接口挂在练题 router 下（`/api/practice/feed`），内部调用 `content.service.getFeed('practice')` —— 与考试端**同一套查询与可见性判定**，不存在两份口径。

**可见性判定统一在服务端**：`enabled = 1` 且 `target ∈ {scope, both}` 且（`start_at` 为空或已到）且（`end_at` 为空或未过）。前端不重复实现，避免两端各算一遍产生偏差。排序：公告置顶优先 + 创建时间倒序，轮播按 `sort_order` 升序；单次下发上限公告 20 / 轮播 10。

**审计**：新增动作 `content.create` / `content.update` / `content.delete` 与目标类型 `announcement` / `banner`（含中文文案）。

**踩坑记录**：`contentListQuerySchema` 的 `enabled` 过滤**不可用 `z.coerce.boolean()`** —— JS 中 `Boolean('false') === true`，会把前端传来的字符串 `'false'` 误判为「只看启用项」，导致筛选失效；改为显式解析 `'true'/'1'/'false'/'0'`。

### 7.3 管理端页面

新增「公告与轮播」菜单（归入**考试运营**组，key `content`，路由 `/admin/content`），页内两个页签：

- **公告管理**：范围 / 状态筛选 + 关键字搜索；列表含置顶标记、级别、生效状态（生效中 / 未生效 / 已过期 / 已停用）、生效时间窗、创建人；
- **轮播图管理**：缩略图预览、跳转地址、排序值；
- 弹窗表单：发布范围（两端 / 仅考试端 / 仅练题端）、级别、置顶、启停、开始 / 结束时间（各自可清空）、轮播图**上传**（复用对象存储附件，也可直接粘贴图片地址）。

### 7.4 双端展示

- **考试端**：新增公共组件 `ContentBoard.vue`（轮播 + 公告列表 + 公告详情弹层），接入「我的考试」页顶部，v1.9⑦ 首页直接复用；无生效内容时**整体不渲染**。
- **练题端**：新增 `PracticeNoticeCard.vue`（移动端样式：轮播 130px + 公告卡，超过 3 条折叠），接入练题首页问候语之后。

**测试**：`server/src/test/v19c.test.ts`（29 例）：权限、CRUD、入参校验（含时间窗 `endAt > startAt`）、列表过滤、**双端可见性矩阵**（发布范围 × 启停 × 时间窗 × 置顶）、练题端接口、审计留痕。

   脚本已追加 `announcements` / `banners` 两表的 **SELECT 授权**（练题实例只读展示）。**若跳过此步，练题端 `GET /api/practice/feed` 会因权限不足报错**（练题首页内容卡静默降级不显示，但日志会持续出现查询失败）。

3. **前端重新构建发布**：根目录 `npm run build`（考试端 / 管理端）与 `practice-web: npm run build`（练题端）产物分别部署。

4. **上线后自检**：
   - 管理端「考试运营 → 公告与轮播」新建一条公告（范围选「两端同步」）与一张轮播图；
   - 考生登录落在 **`/exam/home`**，可见轮播、公告、统计与快捷入口；
   - 练题端首页问候语下方出现同一内容卡；
   - 管理端「练题端设置 → 练题题库」确认目标题库已开放，练题端题库列表非空。

## 14. 已知限制与注意事项

1. **公告正文为纯文本**（保留换行，`white-space: pre-wrap`），不支持富文本 / Markdown —— 有意收敛 XSS 面；如需富文本可复用 v1.7③ 的净化白名单能力。
2. **公告无已读回执**：详情以弹层展示，不记录阅读状态，也不支持「重要公告强制弹窗」。置顶与「重要」级别仅影响排序与样式。
3. **内容下发为一次性截断**：双端单次最多取 20 条公告 / 10 张轮播（按优先级截取），超出部分不展示，也不支持翻页；历史公告需在管理端下架。
4. **轮播图上传仅限管理端**：附件上传接口在考试域（练题实例不注册），练题端只做只读展示。
5. **考生首页统计为即时计算**：口径基于「考生可见的考试列表 + 最近 100 条成绩记录」，记录超过 100 条时平均分按最近 100 条计；不做后端聚合。
6. **`enabled` 布尔过滤的解析坑**：新增查询参数切勿直接用 `z.coerce.boolean()`（`'false'` 会变 `true`），已在 `content.schema.ts` 内置正确的解析器，后续参数建议沿用。
7. **练题端授权脚本必须与表变更同步维护**：任何新增的、练题端需要读取的表，都要在 `deploy/db-grants-practice.sql` 中追加授权，否则公网实例会静默降级。

## 15. 后续建议（v2.0 候选）

按「用户价值 / 实施成本」排序，供下一轮迭代取舍：

1. **公告富文本与图片**：复用 v1.7③ 净化 + v1.8④ 附件存储，支持图文公告；辅以「重要公告首次进入强提醒」。
2. **考生首页数据后端化**：把统计（含及格率、最近成绩趋势、待办提醒）收敛为一个聚合接口，支持全量口径与更快首屏。
3. **公告已读 / 触达统计**：记录阅读回执与轮播点击，形成简单的触达看板。
4. **内容定时上下线**：当前仅支持时间窗，可加「预约发布」与批量上下线（复用 v1.8③ 的调度器与单飞机制）。
5. **练题端打卡与激励**：基于既有 `practice_daily_tasks` 增加连续打卡天数、成就徽章（练题端首页展示）。
6. **考试端首页个性化**：按科室 / 角色下发差异化快捷入口与推荐练题题库。
