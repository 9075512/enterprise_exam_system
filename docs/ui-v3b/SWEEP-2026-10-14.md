### A. 文案与后端实现不符（真实缺陷，已修正）

这类问题最危险——用户按界面提示操作会得到与预期不符的结果。共 4 组：

| 页面 | 原文案（错误） | 后端真实实现 | 处理 |
|---|---|---|---|
| `exam/MyExamPage` 考试须知 | 「切屏累计达 60 秒…记为异常」 | `settings.cheatSecondsThreshold = 120` | 改为读配置，动态渲染 |
| `exam/MyExamPage` 考试须知 | 「开考后 15 分钟未进入视为**缺考**」 | **后端无「缺考」状态**（`RecordStatus` 仅 `in_progress/submitted/pending_review`） | **删除该条**（无对应逻辑，属虚构规则） |
| `exam/MyExamPage` 考试须知 | 「成绩取最高分」 | 成绩取**最近一次**作答（`exams.service` 重考口径） | 改为真实口径 |

## 二、判断依据汇总

1. **后端实现优先于设计稿文案**：设计稿中的业务规则文字是示意，凡与 `server/` 真实逻辑冲突，一律改文案；确属「设计稿有、后端无」的规则（缺考、开卷/闭卷），移除而非伪造。
2. **阈值零硬编码**：所有数字阈值引用 `settingsStore.settings`，与 `settings.defaults.ts` 同源。
3. **统一取「更正式 + 更高频」词**：术语收敛到单一定名，避免同概念多名。
4. **无源字段不占位**：后端不存在的字段（考试形式）不保留硬编码前缀，符合「不造数」红线。
5. **自动可判即改，产品语义留待确认**：涉及信息架构、是否新增配置项、是否新增业务状态的，不擅自决定。

## 五、2026-10-15 追加变更：放开补考资格的次数限制（用户产品决策）

**背景**：原规则要求「该考试答题次数为 1 次」才可申请补考，导致**多次作答的考试在用尽全部次数仍未及格时反而无法补考**（业务死角）。

**改动**（移除该条件，不再限定考试答题次数）：

| 层 | 文件 | 改动 |
|---|---|---|
| 后端 | `server/src/modules/exams/exams.service.ts` | `canApplyRetake` 去掉 `dto.maxAttempts === 1` |
| 后端 | `server/src/modules/retakes/retakes.service.ts` | 移除申请时的 `maxAttempts !== 1` 拦截及错误提示；更新文件头规则注释 |
| 前端 | `src/views/admin/ExamFormDialog.vue` | 「补考申请」项去掉按 `maxAttempts` 分支的提示，统一为「不及格考生可申请补考，经管理员审批通过后追加一次答题机会」 |
| 前端 | `src/views/admin/SettingsPage.vue` | grading 域描述 + 补考开关提示去掉次数限定 |
| 前端 | `src/views/admin/RetakeManagePage.vue` | 「补考资格」= 未及格（不限答题次数） |
| 前端 | `src/views/exam/MyExamPage.vue` | 考试须知「未及格可申请补考」去掉「（仅限单次作答的考试）」 |
| 前端 | `src/views/exam/MyRetakePage.vue` | 规则卡与「选择考试」下方提示同步 |

> 注：本节第一版**仅移除**次数限制；用户随后确认再追加「次数已用尽」条件，**最终口径见本节末尾的追加段**。

**未改动**：`records.service.ts` 的授予逻辑 `maxAllowed = maxAttempts + (retakeGranted ? 1 : 0) + extraAttempts` 本就与次数无关，审批通过后照常追加 1 次机会。历史 PRD（`docs/03-PRD-increment.md`、`docs/09-PRD-v1.5.md`）为版本快照，不追溯修改。

**同轮追加（用户确认「需要」）**：补考资格再加「答题次数已用尽」前置条件，口径 = `attemptsUsed >= maxAttempts + extraAttempts`（含特殊安排的额外次数）：

| 层 | 文件 | 改动 |
|---|---|---|
| 后端 | `server/src/modules/exams/exams.service.ts` | `canApplyRetake` 增加 `attemptsUsed >= maxAllowed`（复用列表已有的 `usedMap` / 特殊安排 `extraAttempts`） |
| 后端 | `server/src/modules/retakes/retakes.service.ts` | `apply` 增加次数校验（`countSubmittedByExamAndUser` + `exceptionsRepo.findByExamAndUser`）：未用尽 → 1001「答题次数尚未用完，请直接继续作答，无需申请补考」 |
| 前端 | 5 处文案 | 资格描述统一为「未及格，且答题次数已用完」（`MyRetakePage` / `RetakeManagePage` / `MyExamPage` / `ExamFormDialog` / `SettingsPage`） |
| 测试 | `server/src/test/retake.eligibility.test.ts`（**新增 6 条**） | 次数未用尽被拒 · 用尽可申请 · 上限含额外次数 · 已提交申请不重复入口 · 已及格回归保护 |

**最终口径**：`allowRetake && 未及格 && 答题次数已用尽 && 无有效申请 && 无进行中作答`。
