# 角色管理升级说明

账号现在直接分配一个角色。角色以管理员、出题人或考生为基础身份，菜单权限在该身份可访问的范围内配置；考试资格、科室要求、出题及阅卷规则仍按基础身份判断。菜单配置控制页面入口，业务接口继续执行基础身份与原有资源权限校验。

## 使用方式

- 在“组织与系统 → 角色管理”新增角色，填写名称、基础身份、说明和菜单权限。基础身份创建后不能更改。
- 新角色默认复制对应内置角色当前菜单，之后独立维护。内置角色不能改名或删除。
- 用户管理直接单选角色；角色成员页也可分配成员。加入角色会替换原角色，移出自定义角色后回到对应身份的内置角色。内置角色的成员请通过用户管理切换角色。
- 存在成员或被抽考模板引用的角色不能删除。管理员必授菜单不能取消，最后一个启用管理员不能被移走、停用或删除。
- “菜单权限”页与角色管理共用授权数据。角色或菜单改变后，受影响成员的会话被撤销，需要重新登录。个人菜单例外继续保留，且不能超出基础身份范围。
- 岗位管理独立保留。Excel 用户模板的第三列改为“角色”，填写已有角色名称；兼容内置身份的英文代码。旧“用户组”模板需重新下载。
- 抽考模板使用 `roleIds` 按考生身份角色圈选，科室、岗位、明确包含/排除人员及随机抽取仍按原规则生效。

## 部署顺序

1. 停止应用写入，备份业务数据库，并确认备份可恢复。
2. 在服务器项目根目录执行 `npm --prefix server run db:init -- --skip-seed`。不要使用 `--reset`。该命令升级现有数据库，并跳过演示数据写入。
3. 构建并发布后端和前端：`npm run build:server`、`npm run build`，随后重启服务。
4. 核对用户数量、基础身份、菜单授权、抽考模板、历史考试冻结名单和题库可见/编辑人员，再恢复流量。

迁移为用户增加 `role_id`，已有账号按当前 `users.role` 归入三个内置角色；旧用户组名称不会转换为自定义角色。角色名称、菜单和用户关联不会在重复初始化时被重置。

历史组圈选范围展开为迁移时的明确用户 ID，与原模板的明确包含人员合并，保留排除、科室、岗位和随机抽取规则。此后不会跟随历史组变化；新规则可改用 `roleIds`。已有冻结名单及准考证不重算。

历史科目授权先按原有允许、拒绝和继承规则计算，再展开到题库的具体可见人员和出题人授权；停用账号的权限也保留，便于未来重新启用。迁移报告保存在 `bank_tree_migration_reports`，`roles-v1` 记录用于防止再次套用历史组授权。

旧用户组表与成员表仅作历史迁移及回退依据，维护端点已停用，日常业务不再读写。新旧前后端需一同升级；旧客户端的基础身份 `role` 入参仍可映射内置角色。

## 验收与回退

确认三个内置角色、独立岗位入口、自定义角色登录、菜单范围、成员转移、Excel 导入及角色抽考可用；确认角色变更后旧会话失效，且不能移走最后一个启用管理员。

回退前应停止写入，并恢复升级前的数据库备份与对应代码。仅回退旧代码会失去升级后新增的角色分配语义；不要直接删除历史组表、新增角色表或外键。
